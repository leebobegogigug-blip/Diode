# Diode 매뉴얼

> **개발 중 (v0.0) — 지어낸 자료 (합성 자료) 로만 시험했습니다. 사내 확인 (Windows · 사내 CLI · 보안 부서의 답) 이 아직 안 끝났으니 실데이터에는 쓰지 마세요.** 이 문서는 지금 있는 기능을 설명합니다. 아직 없는 것은 "아직 없다" 고 적습니다.

**이름은 비유입니다 — 하드웨어 데이터 다이오드가 아닙니다.** 일방향 망연계 장비와 같은 보증을 주지 않습니다.

Diode 는 Claude Code 에 설치하는 플러그인 (프로그램에 끼워 넣는 부품) 하나입니다. 스킬 (Claude 에게 주는 안내 글) · 훅 (Claude 가 글을 받거나 도구를 쓰기 전에 먼저 검사하는 장치) · MCP 허브 (Claude 와 안쪽 일꾼 사이를 잇는 중계 프로그램) · 명령 · 표준 라이브러리 프로그램 (따로 설치할 것 없이 파이썬에 들어 있는 부품만 쓰는 프로그램) 이 한 묶음으로 들어갑니다 ([기획서 › 00](PLAN.md#00-한-장-요약)). 이 문서의 표와 절은 지금 코드에 있는 것을 설명합니다.
소개는 [README](../README.md), 설치 절차는 [INSTALL.md](../INSTALL.md), 사내에서만 끝낼 수 있는 마무리의 경계는 [INHOUSE.md](INHOUSE.md) 에 있습니다.

## 이 도구가 못 하는 것

도구가 있다고 해서 "이제 안전하다" 고 믿으면 안 되기 때문에, 못 하는 것부터 먼저 적습니다 ([기획서 › 02](PLAN.md#02-먼저-정할-것--이-도구가-할-수-없는-일)).

1. **허용 범위는 회사가 정합니다.** 어떤 등급의 무엇을 Claude 로 보내도 되는지는 보안 부서가 정합니다. 이 도구는 그렇게 정한 범위를 기계로 지켜 주는 장치일 뿐입니다. 아무도 정해 주지 않으면 기본값은 **아무것도 안 보냄** 입니다. 법적 판단 · 회사 승인 · 회사 망 DLP (회사 밖으로 나가는 자료를 지켜보는 장치) 를 대신하지 못합니다.
2. **같은 PC 안에는 단단한 벽이 없습니다.** 사내 LLM 이 셸 (명령을 직접 입력해 실행하는 창) 을 쓸 수 있으면, 그 계정이 할 수 있는 일은 모두 할 수 있습니다 (`claude` 를 직접 부르기 · 설정 파일 고치기). 여러 겹으로 막아 두었지만 벽은 아닙니다.
3. **사람이 마지막 문입니다.** 확정 창이 떠도 읽지 않고 누르면 소용없습니다.
4. **너무 많이 막으면 사람은 도구를 끕니다.** 쓰기 쉬운 것도 보안의 한 부분입니다.
5. 보안 부서가 허용 범위를 정하기 전까지 **실데이터는 쓰지 않습니다** (AL-10).

## 설정

설정은 데이터 폴더의 `config.json` 에 들어 있고, 사람이 정책 창 (`/diode:dict`) 에서 바꿉니다 (아래 [데이터](#데이터) 표). 설정 키 · 기본값 전체는 [명세 › SP-15](SPEC.md#sp-15-설정-format-1) 에 있고, 이 문서에는 따로 옮겨 적지 않습니다. 보안에 걸린 설정 (사전 위치 · 검사 문턱 · 정책) 은 환경 변수 (프로그램 밖에서 값을 넘기는 장치) 나 명령줄로 바꿀 수 없습니다. 테스트용 `DIODE_HOME` 만 예외입니다.

## 쓰는 법

쓰는 법을 한곳에 모은 안내는 아직 없습니다. 명령마다 하는 일은 아래 [명령](#명령) 표에 있고, 설치 순서는 [INSTALL.md](../INSTALL.md) 에 있습니다. 이 절에는 사람이 창에서 직접 하는 일 중 하나를 자세히 적습니다.

### 사내 말로 Claude 에게 물을 때 — `/diode:speak`

사내 단어를 Claude 에게 직접 치면 훅이 막습니다. 그런데 막기만 하면 사람이 도구를 꺼 버리므로, 사내 말은 **말 봉인 창** 에서 씁니다. 봉인은 사전에 있는 사내 단어를 가명 토큰 (진짜 단어 대신 넣는 임시 이름표) 으로 바꿔 봉하는 일입니다.

1. `/diode:speak` 를 칩니다. 방 밖의 세션에서 치세요. 방은 셸을 막아 놓아서 슬래시 명령이 돌지 않을 수 있으니, 방 안에서는 방 밖의 터미널에서 `python "<diode 자리>/diode.py" speak` 로 직접 엽니다. 창은 따로 떠 있고 명령은 창을 기다리지 않습니다. 이 명령은 사내 단어를 묻지도 받지도 않습니다.
2. 창 왼쪽 **01 사내 말로 쓰기** 에 사내 말로 씁니다. [봉인] 을 누르면 사전 단어가 가명 토큰 (`PH_K7Q2` 꼴) 으로 바뀐 글이 **02 봉인한 글** 에 뜹니다. 같은 단어는 늘 같은 토큰입니다.
3. **03 검사** 줄을 봅니다. 바꾼 글을 숫자 (D4) · 경로 · 주소 꼴 (D3) · 사전 (D2) · 토큰 (D6) 으로 다시 검사합니다. 걸리면 [복사] 가 꺼지고 검사 번호와 줄 번호만 보입니다 (단어는 보이지 않습니다). 그러면 쓴 글을 고치고 다시 [봉인] 합니다.
4. 봉인한 글을 **눈으로 확인** 한 다음 [복사] 를 눌러 Claude 에 붙여 넣습니다. 복사는 클립보드 (복사해 둔 글이 잠깐 머무는 곳) 에 넣은 글을 다시 읽어서 같을 때만 성공입니다. 쓴 글을 고치면 복사는 곧바로 꺼지고, 다시 봉인해야 켜집니다.
5. Claude 의 답을 오른쪽 **04 Claude 의 답** 에 붙여 넣고 [되돌려 보기] 를 누르면, 아는 토큰만 진짜 말로 바뀐 글이 **05 되돌린 글** 에 뜹니다. 모르는 토큰 · 깨진 토큰 (U1) 과 바깥 주소 (U3) 는 줄 번호만 알려 줍니다. 답에 사전 단어가 들어 있으면 (U2) Claude 가 진짜 단어를 맞혔을 수 있으므로, 되돌린 글을 만들지 않고 경고만 냅니다.
6. 끝나면 닫습니다. [비우기] 는 글 칸을 모두 비우지만 가명 표 (토큰과 진짜 단어의 짝을 적은 표) 는 남깁니다.

한계를 솔직히 적습니다.

- **되돌린 글은 이 창에서만 보입니다.** 복사 단추가 없고, 복사 · 잘라내기도 막았고, 파일 · 클립보드 · 로그에 쓰지 않습니다. 하지만 화면 캡처와 눈으로 옮겨 적기는 막지 못합니다.
- **창을 닫으면 가명 표가 사라져서 답을 되돌릴 수 없습니다.** 표는 메모리에만 있습니다 (디스크 · 임시 파일 · 출력에 쓰지 않습니다). 토큰이 남은 채 닫으려 하면 한 번 더 묻습니다. 손대지 않은 채 30분이 지나면 표를 지우고 창도 닫습니다.
- **사전에 없는 단어는 봉인되지 않습니다.** 그래서 봉인한 글을 사람이 눈으로 확인해야 합니다. 이 창이 지켜 주는 것은 사전에 있는 단어뿐입니다.
- **감사 기록에 남지 않습니다.** 사람이 붙여 넣는 길이라서 일반 입력과 같기 때문입니다. 훅이 붙여 넣은 글을 한 번 더 봅니다.
- 봉인한 글 칸을 마우스로 골라 복사하는 것은 [복사] 가 켜진 글일 때만 됩니다. 입력은 글 64 KiB · 답 256 KiB 까지입니다. 보이지 않는 글자가 있거나 `DIODE_HOME` 로 연 창이면 복사하지 않습니다 (`E-20`).
- 사전 · 설정을 읽지 못하거나 사전이 비어 있으면 창을 열지 않고 `E-20` (종료 코드 3) 으로 끝납니다. 화면이 없으면 `E-07` (종료 코드 1) 입니다.

- `check` 가 `결과: 확인 필요` (종료 코드 3) 를 내는 때는 환경 변수 `DIODE_HOME` 이 설정되어 있을 때입니다. 그 자리는 테스트용이라서 사람이 한 번 확인하게 합니다.

### 파생 표본 — `derive`

Claude 가 화면이나 기획을 도우려면, 가끔 표의 **모양** 만으로는 모자라고 값들이 **어떻게 퍼져 있는지 (분포)** 가 필요합니다. 하지만 실값은 보낼 수 없으므로, 사람이 안쪽 터미널에서 표 파일 (CSV · UTF-8) 을 아주 거칠게 줄여서 `sample` 칸으로 냅니다. **기본은 꺼짐입니다.**

1. **켜기** — 정책 창 (`/diode:dict`) 의 선택 구역에서 실데이터를 허용하고 (확인 글 `사내 자체 검증 완료`) **파생 표본** 칸을 켭니다 (같은 확인 글). 환경 변수 · 명령줄 · `--set` 으로는 켤 수 없습니다. 실데이터 허용이 꺼지면 이 칸도 꺼집니다 — 실데이터 승인 없이는 어떤 값으로도 돌지 않습니다.
2. **돌리기** — 안쪽 PC 의 터미널에서 `python "<diode 자리>/diode.py" derive "<표.csv>" --out "<초안.json>"`. 터미널이 아닌 입력 (파이프) 이나 `DIODE_HOME` 으로 연 자리에서는 돌지 않습니다.
3. **고르기** — 묻는 대로 주제 job 번호 (`J-0007` 꼴 · 파생 자료 누계를 이 번호로 셉니다) → **원본 표의 전체 행 수** (정수 · 1,000 이상) → k (10 이상 · 비우면 10) → 열마다 `열=변환` 을 한 줄에 하나씩 적고 빈 줄로 끝 → `y`. 열은 머리 글을 그대로 치거나 1부터의 번호입니다. **변환을 안 적으면 (열 이름만 적으면) `bucket` 입니다.** `rank` 는 직접 `열=rank` 로 쳐야 하고 최대 2열입니다. 적지 않은 열은 나가지 않습니다. 이 선택은 파일에 저장하지 않고, 묻는 글에도 열 이름이 나오지 않습니다.
4. **원본 행 수는 사람이 말해 주는 값입니다.** 표 파일은 원본에서 뽑은 표본 50행 이하뿐이라 `derive` 가 원본이 몇 행인지 스스로 알 수 없습니다. 알려 주신 수를 믿고 한도를 계산하므로, **벽이 아닙니다.** 큰 수를 말하면 한도를 속일 수 있고, 막는 것은 확정 창에서 사람이 표를 보는 일입니다 (감사 기록에 알려 준 수가 정수 하나로 남습니다).
5. **같은 원본에서 job 을 나눠 뽑을 때는 job 사이에 같은 행이 겹치지 않게 뽑으세요.** 같은 행이 여러 job 에 들어가면 모아서 맞춰 볼 수 있습니다 (시뮬레이션은 겹치지 않는 경우만 쟀습니다). `derive` 는 파일의 값을 저장하지 않으므로 겹치는 행을 자동으로 막지 못합니다 - 사람이 지키는 절차입니다.

| 변환 | 열 | 나가는 칸 |
|---|---|---|
| `bucket` (기본) | 숫자 | 분위수 경계로 0–4 한 칸 (`열=bucket:0.2,0.4,0.6,0.8` 으로 수준을 고를 수 있습니다 · 경계값은 나가지 않습니다) |
| `rank` | 숫자 | 순위 백분위를 0–9 한 칸 (동률은 같은 칸) · 최대 2열 · 직접 `rank` 라고 쳐야 함 |
| `category` | 범주 | 이 자문의 가명 토큰. 행이 k 미만인 값은 `PH_other` 하나로 묶습니다 |

열 이름은 가명 토큰과 종류 (`수치` · `범주`) 로만 나갑니다. 한도 (넘으면 거절 · 모두 `E-31`): 열 8 · 행 50 (원본이 5,000행 미만이면 30) · 행 수 k × 2 미만의 작은 표 · k 10 미만 · 원본 1,000행 미만 · `rank` 열 3개 이상 · 한 주제의 파생 누계 행은 200 과 원본 행 수의 10% 중 작은 쪽 (원본 1,000행이면 100행). 이 한도의 근거는 [재식별 시뮬레이션](../kit/results-reid.md) 입니다. 출력 행은 칸 값으로 정렬해서 원래 표의 행 순서가 새지 않습니다. 만든 초안은 `seal` 로 미리 봉인해 검사 (D1–D6) 를 통과해야 쓰입니다. 감사 기록에는 변환 종류별 열 수와 행 수, 알려 주신 원본 행 수 (정수 하나) 만 남습니다 (값 · 열 이름 없음).

**한계를 솔직히:**

- **정보의 양은 줄었을 뿐 0 이 아닙니다.** 한 칸은 `bucket` 최대 약 2.3 bit · `rank` 약 3.3 bit · 범주 약 3.5 bit 이고, 열 8 × 행 50 이면 **최대 약 1,300 bit** 입니다. 이 정보로 누군가를 **통계적으로 다시 알아낼 수 있는지는 증명할 수 없습니다** (공개 자료와의 대조 · 이상치 · 열 조합). 시험이 보이는 것은 실값 · 열 이름 · 경계값의 글자가 나가지 않는다는 것뿐입니다. 허용할 등급 · 합격선은 보안 부서가 정합니다 ([제안 문서](PROPOSAL-derived.md)).
- **같은 주제에 여러 번 보내면 정보가 쌓입니다** (모자이크). 그래서 주제당 누계는 200행과 원본 행 수의 10% 중 작은 쪽까지입니다.
- **초안을 Claude 에게 보내려면 `propose` 로 냅니다.** 사람이 같은 터미널에서 `python "<diode 자리>/diode.py" propose "<초안.json>"` 을 칩니다. `derive` 가 만든 초안 그대로여야 하고 (칸을 더하거나 표를 고치면 `E-04`), 정책 창에서 켜 둔 상태여야 하고, 입력이 터미널이어야 합니다 (아니면 `E-30`). 일꾼 (사내 LLM) 이 쓴 plan · ui 를 받는 문이 아닙니다. 그러면 방의 허브가 검사 (D1–D7) 하고 **확정 창에 표를 보낼 바이트 그대로 보여 줍니다** — 창에는 "표가 들어 있습니다 (n열 · n행) · 이 표는 실값에서 줄인 값이고 재식별이 안 된다고 증명할 수 없습니다" 한 줄이 더해집니다. 사람이 [보내기] 를 눌러야 방의 `outbox` 로 갑니다. 한 job 에는 한 번만 보낼 수 있고, 감사 기록에는 보낸 글 그대로 · 해시 · 변환 종류별 열 수 · 열 수 · 행 수가 남습니다.
- **이 토큰들은 되돌릴 수 없습니다 (일방향 토큰).** 열 이름 · 범주 값의 가명 표는 `derive` 가 끝나면 사라지고 (디스크에 쓰지 않습니다) 허브에도 없습니다. 그래서 검사 (D6) 는 `derive` 감사 기록에 적힌 토큰 수 안의 정확한 꼴이면 통과시키고, Claude 의 답에 이 토큰이 있어도 되돌리지 않습니다 (말 봉인 창의 되돌리기에서는 모르는 토큰입니다). 답의 토큰이 어느 열인지는 `derive` 를 돌릴 때의 열 번호로 사람이 찾습니다. 표 글의 해시가 `derive` 기록과 맞는 초안만 받으므로 지어낸 표 · 고친 표는 받지 않지만, 이것은 벽이 아닙니다 — 초안 파일을 읽을 수 있는 쪽은 그대로 낼 수 있고, 막는 것은 확정 창에서 사람이 표를 보는 일입니다. 허브가 여럿이면 먼저 읽은 허브의 방으로 갑니다. 사내 LLM 의 판정 (D7) 이 표의 한 자리 숫자를 수치로 보고 막을 수도 있습니다 (막으면 보내지 않습니다).
- 터미널 확인 (파이프 거부) 은 벽이 아닙니다. 같은 계정의 셸을 쥔 쪽 앞에서는 PC 안의 어떤 장치도 단단하지 않습니다 (L-11).

### 공개 이름 목록 — `lib names <이름>`

라이브러리 질문 (`kind: "lib"`) 의 합성 재현 코드는 허용 라이브러리의 **공개 이름** 만 쓸 수 있습니다 (나가는 검사 D5a). 그 이름 목록을 안쪽 PC 에 설치된 판에서 뽑는 명령입니다. 사람이 안쪽 PC 의 터미널에서 직접 돌립니다 — Claude 가 부르는 길이 아니고, 쓰는 자리 (`libnames/`) 는 데이터 폴더라서 Claude 가 읽지도 고치지도 못합니다.

- `<이름>` 은 import 이름이고 설정의 라이브러리 허용 목록 (`policy.lib_allow`, 정책 창 `/diode:dict` 에서 사람이 적습니다) 에 있어야 합니다 (대소문자 무시). 없거나 파일 이름으로 쓸 수 없는 꼴이면 종료 코드 2 와 고정 문구뿐입니다 — 입력한 이름을 되풀이하지 않습니다.
- 라이브러리는 **별도 프로세스** 에서 불러옵니다 (인자 목록 · 셸 없음 · 시간 상한 60초 · 출력 상한 2 MiB). 그 프로세스의 오류 출력은 버립니다 (라이브러리가 경로를 찍을 수 있습니다). 불러오지 못하면 (설치 안 됨 포함) 종료 코드 1 이고 아무것도 쓰지 않습니다.
- 모으는 이름: 모듈의 공개 속성 (`_` 로 시작하지 않는 것) · 그 라이브러리 안에서 **이미 불러와진** 하위 모듈과 클래스의 공개 멤버 (깊이 3 까지) · 함수의 키워드 인자 이름. 모든 하위 모듈을 불러오지는 않습니다 — 불러오는 코드의 범위를 키우지 않으려는 것이라, 게으르게 불러오는 부분의 이름은 빠질 수 있습니다 (빠진 이름은 D5a 가 막습니다). 이름은 20,000개까지이고 넘으면 자르고 `truncated: true` 로 적습니다.
- 결과 파일 `libnames/<소문자 이름>.json`: `{"format": 1, "library": "<이름>", "version": "<설치된 판 · 모르면 빈 글>", "names": [정렬된 목록], "truncated": false}`. 원자적으로 쓰고, 같은 이름의 파일만 새로 씁니다 (다시 돌리면 갱신). 더 새 형식이면 덮어쓰지 않고, 깨져 있으면 `.broken` 으로 옮깁니다.
- 실패의 `error` 코드 (`{"ok": false, "error": …}`): `config` (설정을 못 읽음) · `not_installed` · `timeout` · `too_large` · `failed` · `bad_output` · `newer` · `write`.

## 알려진 한계

- **실데이터에는 아직 쓰지 마세요 (v0.0).** 훅 · 허브 · 확정 창 · 정책 창 · 명령까지 있고 합성 자료로 진짜 Claude CLI 와 opencode 를 붙여 시험했습니다. 그러나 사내 Windows · 사내 CLI 판 · 보안 부서의 답은 아직 확인 전입니다.
- **설정 전에는 그 밖의 폴더가 지켜지지 않습니다.** 데이터 폴더에 사전 · 설정이 없으면 훅은 그 밖의 폴더의 말을 통과시키고 세션 시작 때 알리기만 합니다 (방은 설정 없이 막습니다). 사전 · 설정이 깨져 있으면 막습니다.
- **플러그인을 끄면 보호가 없습니다.** 훅은 플러그인이 켜져 있을 때만 돕기 때문입니다.
- **상태 명령의 `seatbelt: on` 은 플러그인이 켜졌다는 뜻이 아닙니다.** 설정 (사전 · 원자료 폴더 목록) 이 있다는 뜻입니다.
- **D7 판정 (사내 LLM) 은 환경 변수 덮어쓰기를 받지 않습니다.** `llm` 설정의 `{env:이름}` 참조도 받지 않습니다. 다만 `ca_file` (접속하는 서버가 진짜인지 확인할 때 쓰는 인증서 파일의 자리) 을 적지 않으면, 그 자리를 OpenSSL (암호화 접속을 맡는 부품) 이 `SSL_CERT_FILE` 환경 변수에서 찾을 수 있습니다. 그러니 `ca_file` 을 적으세요. 설정에 프록시 (접속을 대신 전달해 주는 중간 서버) 주소를 적은 경우에만 `no_proxy` 를 봅니다.
- **확정 창의 글은 마우스로 골라 복사할 수 있습니다.** 손으로 옮긴 글은 감사 기록에 남지 않습니다.
- **확정 창은 화면이 있어야 뜹니다.** 화면이 없는 환경 (원격 셸 · Windows 밖에서 `DISPLAY` 없음) 에서는 보내지 않습니다 (`E-07`). 글꼴은 Unifont 가 있으면 그것, 없으면 Consolas · D2Coding 순입니다.
- **안쪽 도구 (opencode) 는 Claude 가 직접 부를 수 없습니다.** CLI 안에 opencode 가 물려 있어도 훅이 막습니다 (이름에 `opencode` 가 든 MCP 도구 · 하위 에이전트 · 스킬 · 셸 명령). 다른 이름으로 물렸다면 설정 `policy.inner_tools` 에 이름 조각을 더하세요. 안쪽 일은 허브로만 넘깁니다.
- **일꾼 전용 opencode 에이전트를 하나 만들어 권한을 좁히세요 (두 번째 층).** 안내문은 벽이 아닙니다 (AL-09) — 일꾼이 셸이나 파일 쓰기로 방 (Claude 가 읽는 자리) 에 확정 창을 거치지 않고 글을 두는 길을 opencode 쪽에서 닫습니다. **평소 쓰는 opencode 의 전역 권한은 건드리지 않고** 이 에이전트에만 권한을 줍니다 (opencode 설정 · 규칙은 **나중에 적은 것이 이깁니다** — 전부 거절 `*` 를 맨 앞에 · 패턴은 Windows 경로의 역슬래시에도 맞게 `*diode.py` 꼴):
  ```json
  {"agent": {"diode-worker": {
      "description": "Diode 일꾼", "mode": "primary",
      "permission": {
        "bash": {"*": "deny", "python *diode.py propose *": "allow", "python3 *diode.py propose *": "allow"},
        "edit": "allow", "external_directory": "deny", "webfetch": "deny"}}}}
  ```
  `edit: allow` 는 일꾼의 작업 폴더 안에서만 듣습니다 (`external_directory: deny` 가 폴더 밖 — 방 포함 — 을 막습니다). `opencode run --auto` (권한 자동 승인) 는 쓰지 않습니다. 이 설정은 진짜 opencode 1.19.5 로 확인했습니다 (`kit/run_opencode.py` R2–R4 — 허락한 `propose` 는 돌고, 허락하지 않은 명령은 작업 폴더 **안에서도** 안 돌고, 방에는 못 쓰고, 에이전트를 안 쓰면 전역 설정 그대로).
- **일꾼은 설정 `worker.command` 가 있어야 돕니다.** 일꾼은 안쪽에서 사내 LLM 으로 일하는 프로그램입니다. 예: `["opencode", "run", "--agent", "diode-worker", "--dir", "{cwd}"]` — 프롬프트는 표준 입력으로 줍니다 (`{prompt}` 를 적지 않으면 그렇게 됩니다). `--dir` 을 빼면 opencode 의 셸이 일꾼의 작업 폴더 밖에서 돌아 보고 파일을 찾지 못합니다.
- **Windows 에서 opencode 가 `.cmd` 껍데기 (실행을 대신 걸어 주는 작은 파일) 면 `{prompt}` 를 인자로 주지 마세요.** `cmd.exe` 가 인자를 다시 해석해서 프롬프트 (Claude 가 쓴 글) 의 `&` · `|` · `^` · `%` 가 명령이 됩니다 (명령 주입). Diode 는 이 조합을 거절하고 (`일꾼 명령 문제: cmd_shim_prompt`) 표준 입력을 쓰게 합니다. 진짜 opencode 는 표준 입력 (글을 흘려 넣는 길) 으로 받고 특수문자도 그대로 옵니다.
- **안내 파일 (`CLAUDE.md` · `AGENTS.md`) 에 사내 단어가 있으면 프롬프트가 막힙니다.** 안내 파일은 모든 요청에 실려 가므로, 사용자 범위 (`~/.claude`) 와 작업 폴더에서 위로 올라가며 (CLAUDE.md · CLAUDE.local.md · AGENTS.md · `.claude/CLAUDE.md` · `rules/*.md`) 훅이 사전으로 검사합니다. 걸리면 개수만 알리고 (`D2 x<개수> @안내파일`) 보내지 않습니다 — 지우거나 옮기세요. `@` 로 끌어오는 다른 파일 · 하위 폴더의 안내 파일은 보지 않습니다 (알려진 한계). 없으면 `dispatch` 는 `E-01` 입니다. 일꾼의 출력은 읽지 않습니다 — 결과는 일꾼이 `propose` 로만 냅니다.
- **정책 창은 화면이 있어야 뜹니다.** 화면이 없는 환경 (원격 셸) 이나 tkinter 가 없는 파이썬에서는 `E-07` 로 알리고 열지 않습니다 — 정책은 그 창에서만 바뀌므로 화면이 있는 PC 에서 여세요. 창 두 개를 동시에 열면 나중에 저장한 쪽이 이깁니다.
- **사전에는 짧고 흔한 말을 넣지 마세요.** 사전 비교는 띄어쓰기와 문장부호를 지운 글에서 글자 조각을 찾기 때문에, 짧은 단어 (한글 세 글자 이하 · 영문 네 글자 이하) 는 그 글자가 든 평범한 낱말과 문장까지 막습니다. 막힘이 잦으면 사람이 도구를 끄게 되니, 짧은 말 대신 더 긴 이름이나 별칭을 넣으세요. 다른 항목 안에 통째로 들어가는 항목도 같은 이유로 세어 알립니다. 정책 창은 저장한 뒤 `짧은 단어 N개 - 평범한 말이 막힐 수 있습니다 (오탐) …` 한 줄로, `/diode:status` · `setup --check` 는 `사전 짧은 단어 N개 (오탐 위험)` 한 줄로 개수만 알립니다 (단어는 보이지 않습니다). 경고일 뿐 저장을 막지는 않습니다 — 넣을지는 사람이 정합니다.
- **정책 창에서 `llm` 칸을 비우면 지우는 것이 아니라 그대로 둡니다.** 지우려면 `config.json` 의 `llm` 을 직접 지우세요 (사람이 · 데이터 폴더는 Claude 가 못 만집니다).
- **사내 단어가 든 파일은 위치와 상관없이 `Read` 가 막힙니다** (그 밖의 폴더에서). 원자료 폴더 목록에 빠진 폴더도 내용으로 지킵니다. UTF-16 (PowerShell 5.1 의 `>` 출력 · 메모장의 "유니코드" 저장) · CP949 · JSON/HTML 이스케이프도 풀어서 봅니다. `@파일` 로 끌어오는 파일도 같은 검사를 받고, 원자료 폴더 · 데이터 폴더 안의 파일은 끌어오지 못합니다. 다만 이미지 · PDF, `Grep` 의 결과, 셸의 `cat` 은 내용을 못 봅니다 (읽을 수 없는 그 밖의 이진 파일은 읽기를 막습니다) — 사내 자료가 있는 폴더는 원자료 폴더 목록에 넣으세요 (그러면 폴더째로 막힙니다). 2 MiB 가 넘는 파일은 검사하지 못해 막습니다.
- **사전 · 설정은 Claude 가 못 읽고 못 고칩니다.** 데이터 폴더를 가리키는 파일 도구 · 셸 명령은 훅이 막고, 사전 · 원자료 폴더는 정책 창 (`/diode:dict`) 에서 사람이 입력합니다. 사내 단어를 대화에 치면 곧바로 Claude 로 나가므로 슬래시 명령도 단어를 묻지 않습니다. 셸은 벽이 아니라서 (경로를 돌려 말하면 비켜 갑니다) 알려진 한계입니다.
- **`lib names` 는 라이브러리의 코드를 돌립니다.** 이름을 모으려면 라이브러리를 불러와야 하고, 불러오는 동안 그 라이브러리의 코드가 돕니다. 허용 목록에 적은 라이브러리만, 안쪽 PC 에서 사람이 돌립니다. 하위 프로세스는 `PYTHONPATH` 같은 환경 변수와 작업 폴더를 검색 경로에서 빼지만 (사용자 site-packages 는 그대로), 벽은 아닙니다. 명령 자체는 확정 창이 없습니다 — 허용 목록은 정책 창에서 사람이 확정한 것이고, 이 명령은 그 목록의 이름만 받습니다.
- **말 봉인 창은 화면이 있어야 뜹니다** (`E-07`). 그리고 사전에 있는 단어만 가립니다 — 사전에 없는 단어는 그대로 나가므로 봉인한 글을 눈으로 확인하세요. 되돌린 글은 이 창에서만 보이고 창을 닫으면 사라집니다 ([쓰는 법](#사내-말로-claude-에게-물을-때--diodespeak)).
- **파생 표본 (`derive`) 은 재식별을 막는다고 증명하지 못합니다.** 가려서 줄인 값도 정보입니다 (위 상한). 기본은 꺼짐이고 정책 창에서 실데이터 승인과 함께만 켜집니다. 합격선은 보안 부서의 몫이고, 공개 보조 자료와 합쳐 재식별해 보는 공격 시험은 아직 없습니다.
- **플러그인 소스는 세션 안에서 고치지 못합니다** (쓰기 도구 deny). 직접 개발할 때는 이 플러그인을 끄고 여세요.
- **슬래시 명령은 `--report` 로 종료 코드를 늘 0 으로 둡니다.** Claude Code 는 `!` 명령이 0 이 아니면 명령을 실패로 보고 Claude 에게 넘기지 않습니다.
- **훅은 `DIODE_HOME` 을 받지 않습니다.** 늘 기본 데이터 폴더를 봅니다 — 환경 변수로 다른 사전 · 설정을 물리지 못하게.
- **S-09 를 따르지 않습니다.** 나가는 검사 D7 (사내 LLM 판정) 은 works 의 [SPEC-llm](https://github.com/leebobegogigug-blip/Works/blob/13e56a0a5801da56dc18523363cd219ebf6d2e21/docs/SPEC-llm.md) 의 `llm` 설정 키를 따르지만, 환경 변수 덮어쓰기 (`<접두어>_BASE_URL` 등) 는 받지 않습니다. 사내 LLM 이 환경 변수로 판정 모델을 바꿔 D7 을 무력화할 수 있어서 AL-12 와 부딪히기 때문입니다 ([규칙 › S-09](../RULES.md#규약)).
- 이 저장소에서는 사내 TUI · 사내 Windows 를 볼 수 없습니다. 사내에서만 되는 확인은 [사내 마무리](INHOUSE.md) 로 남깁니다.
