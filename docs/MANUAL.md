# Diode 매뉴얼

> **개발 중 (v0.0) — 아직 아무것도 막지 않습니다.** 이 문서는 뼈대입니다. 비어 있는 절은 v0.1 부터 채웁니다.

**이름은 비유입니다 — 하드웨어 데이터 다이오드가 아닙니다.** 일방향 망연계 장비와 같은 보증을 주지 않습니다.

Claude Code 에 설치하는 플러그인 하나입니다. 스킬 · 훅 · MCP 허브 · 명령 · 표준 라이브러리 프로그램이 한 묶음으로 들어갑니다 ([기획서 › 00](PLAN.md#00-한-장-요약)). 지금 있는 것은 그중 뼈대와 자리표시 스킬 · 자가 점검뿐입니다.
소개는 [README](../README.md), 설치 절차는 [INSTALL.md](../INSTALL.md), 사내 마무리의 경계는 [INHOUSE.md](INHOUSE.md) 에 있습니다.

## 이 도구가 못 하는 것

도구가 있다는 사실이 "안전하다" 는 착각을 만들지 않게, 먼저 적습니다 ([기획서 › 02](PLAN.md#02-먼저-정할-것--이-도구가-할-수-없는-일)).

1. **허용 범위는 회사가 정합니다.** 어떤 등급의 무엇이 Claude 로 가도 되는지는 보안 부서가 정합니다. 이 도구는 그 범위를 기계로 지키는 장치일 뿐이고, 정해 주지 않으면 기본값은 **아무것도 안 보냄** 입니다. 법적 판단 · 회사 승인 · 회사 망 DLP 를 대신하지 못합니다.
2. **같은 PC 안에는 단단한 벽이 없습니다.** 사내 LLM 이 셸을 쓰면 그 계정이 할 수 있는 일은 다 합니다 (`claude` 를 직접 부르기 · 설정 파일 고치기). 여러 겹으로 막지만 벽은 아닙니다.
3. **사람이 마지막 문입니다.** 확정 창이 있어도 읽지 않고 누르면 소용없습니다.
4. **너무 많이 막으면 사람은 도구를 끕니다.** 쓰기 쉬움도 보안 성질입니다.
5. 보안 부서가 허용 범위를 정하기 전까지 **실데이터는 쓰지 않습니다** (AL-10).

## 설정

v0.1 에서 채웁니다. 설정 키 · 기본값은 [명세 › SP-15](SPEC.md#sp-15-설정-format-1) 에 있습니다. 보안에 걸린 설정 (사전 위치 · 검사 문턱 · 정책) 은 환경 변수 · 명령줄로 바꿀 수 없고, 테스트용 `DIODE_HOME` 만 있습니다.

## 명령

`python diode.py <명령>` 으로 부릅니다. 종료 코드는 `0` OK · `1` 점검 실패 · `2` 사용법 오류 · `3` 사람 확인 필요이고, 점검 출력의 마지막 줄은 `결과: OK` · `결과: 확인 필요` · `결과: 점검 실패` 중 하나입니다 ([규칙 › S-03](../RULES.md#규약)).

| 명령 | 하는 일 | 지금 (v0.0) |
|---|---|---|
| `version` | `Diode 0.0.1` 을 찍습니다 (`--version` 도 됩니다) | 있음 |
| `help` | 도움말 (`-h` · `--help` 도 됩니다) | 있음 |
| `check` | 자가 점검 — 파이썬 판 (3.8 이상) 과 데이터 폴더 자리를 보입니다. 아무것도 만들거나 바꾸지 않습니다 | 있음 |
| `mcp` | 허브 (MCP 서버) | 아직 없음 |
| `hook <session \| prompt \| tool>` | 훅 | 아직 없음 |
| `--statusline` | statusLine 기록 | 아직 없음 |
| `--status --json [--room 폴더]` | 상태 명령 (바깥 인터페이스) | 아직 없음 |
| `propose <report.json>` | 일꾼 보고 내기 | 아직 없음 |
| `confirm <요청 파일>` | 확정 창 | 아직 없음 |
| `scan` | 표준 입력의 글 검사 | 아직 없음 |
| `lib names <이름>` | 허용 라이브러리의 공개 이름 | 아직 없음 |

- 아직 없는 명령은 `아직 없음 (v0.0)` 을 표준 오류에 쓰고 종료 코드 2 로 끝납니다. 계약은 [명세 › SP-16](SPEC.md#sp-16-명령--종료-코드) 입니다.
- `check` 가 `결과: 확인 필요` (종료 코드 3) 를 내는 때는 환경 변수 `DIODE_HOME` 이 설정되어 있을 때입니다. 테스트용 자리라서 사람이 확인합니다.

### 바깥 인터페이스

Terminal–1 같은 다른 도구가 부르는 읽기 전용 상태 명령 (`--status --json`) 의 칸 · 값 범위는 v0.1 에서 이 절에 적습니다. 아직 없는 명령이라 지금은 부를 수 없습니다.

## 개발

| 할 일 | 명령 |
|---|---|
| 테스트 | `python -m unittest discover -s tests` (표준 라이브러리만 — 스키마 시험에는 `jsonschema` 가 있으면 더 돕니다 · 개발 시험용이고 실행에는 쓰지 않습니다) |
| diode 규칙 검사 | `python tools/diode_check.py` — CI 는 `--strict` |
| 플러그인 · 마켓플레이스 점검 | 저장소 루트에서 `claude plugin validate .` (경고 없이 통과) |
| 파이썬 3.8 에서 | 위 두 명령을 `python3.8` 로도 돌립니다 (CI 가 3.8 · 3.13 에서 돌립니다) |

- CI (`.github/workflows/diode.yml`) 는 Windows · Ubuntu × 파이썬 3.8 · 3.13 에서 테스트와 `--strict` 검사를 돌립니다.
- 검사기는 의존 0 · `0.0.0.0` 바인딩 · 비밀 흔적 · 필수 파일 · README 의 테스트 수 · 사설 주소 · 외부 CDN · 플러그인 파일을 봅니다 ([규칙 › W-11](../RULES.md#w-11-약속은-ci-가-지킨다)). 사내 낱말 검사는 낱말 목록 파일을 줄 때만 돕니다 (`--internal-words <파일>` — 낱말은 찍지 않고 개수만 나옵니다).
- 고칠 때의 규칙은 [AGENTS.md](../AGENTS.md) 에 있습니다.

## 알려진 한계

- **아직 아무것도 막지 않습니다 (v0.0).** 훅 · 허브 · 확정 창이 없습니다. 검사 코드가 자라고 있어도 막는 자리에 걸려 있지 않습니다.
- **S-09 를 따르지 않습니다.** 나가는 검사 D7 (사내 LLM 판정) 은 works 의 [SPEC-llm](https://github.com/leebobegogigug-blip/Works/blob/13e56a0a5801da56dc18523363cd219ebf6d2e21/docs/SPEC-llm.md) 의 `llm` 설정 키를 따르지만, 환경 변수 덮어쓰기 (`<접두어>_BASE_URL` 등) 는 받지 않습니다. 사내 LLM 이 환경 변수로 판정 모델을 바꿔 D7 을 무력화할 수 있어서 AL-12 와 부딪히기 때문입니다 ([규칙 › S-09](../RULES.md#규약)).
- 이 저장소에서는 사내 TUI · 사내 Windows 를 볼 수 없습니다. 사내에서만 되는 확인은 [사내 마무리](INHOUSE.md) 로 남깁니다.
