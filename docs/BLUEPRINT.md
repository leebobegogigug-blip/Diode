# Diode 청사진 — PN 접합으로 읽기

- **누가 읽나**: 반도체 소자를 대학에서 조금 배운 사람이 읽으면 가장 잘 이해돼요. 몰라도 읽을 수 있게 낱말마다 풀어 두었어요. 설계의 정본(기준이 되는 원본)은 [PLAN.md](PLAN.md) 이고, 이 문서는 그 설계를 PN 접합 다이오드 (전기를 한쪽으로만 흐르게 하는 부품) 의 말로 다시 읽어 줘요.
- **측정값**: [실험] 표시는 M0 리눅스판 ([kit/results-linux.md](../kit/results-linux.md) · 2026-11-05 · Claude Code 2.1.318 · 가짜 서버 · 합성 자료) 에서 직접 본 것이에요. 식과 비율은 **비유** 이고 측정값이 아니에요.
- **한 줄**: Diode 는 회사 안 (사내 LLM · 원자료) 과 회사 밖 (Claude) 사이의 접합이에요. 순방향 (밖 › 안 · 지시) 은 흐르고, 역방향 (안 › 밖 · 원자료) 은 막아요. 역방향으로 흐르는 것은 **설계로 정해 둔 작은 누설 — 사람이 확정한 봉인 보고** 뿐이에요.
- **낱말 풀이**: 사내 LLM = 회사 안에서 돌아가는 인공지능. 원자료 = 회사 안에 있는 진짜 자료. 봉인 보고 = 일반적인 말로 다시 쓴, 밖으로 나가도 되는 짧은 보고서.

## 0. 회로 기호와 단자

```text
        애노드 (p)                    접합 · 공핍층                    캐소드 (n)
   바깥: Claude CLI 세션   ───────────▶|───────────   안쪽: 사내 LLM (opencode) · 원자료
                          깨끗한 방 · 허브 · 검사기 · 확정 창 · 기록

   순방향 (애노드 → 캐소드): Claude 의 지시가 안쪽으로 — 흐른다
   역방향 (캐소드 → 애노드): 원자료가 바깥으로 — 막힌다 (작은 의도된 누설만)
```

위 그림은 다이오드 회로 기호예요. 다이오드는 전기가 한쪽 방향으로만 잘 흐르는 부품이고, Diode 는 정보에 대해 같은 일을 해요. 아래 표는 반도체 낱말이 Diode 의 무엇에 해당하는지 짝지어 둔 거예요.

| 소자 | Diode |
|---|---|
| n 영역의 다수 캐리어 (전자) | **원자료** — 안쪽에 넘쳐요 · 바깥으로 넘어가면 안 돼요 |
| n 영역의 소수 캐리어 (정공) | 원자료가 아닌 작은 정보 — 일반 말로 다시 쓴 **봉인 보고** |
| 공핍층 (자유 캐리어가 없는 영역) | **깨끗한 방** (`D:\claude\room`) 과 허브 — 원자료가 하나도 없는 영역 |
| 내부 전위 장벽 V<sub>bi</sub> | 결정적 검사기 D1–D8 · 닫힌 형식 (brief) — 다수 캐리어가 넘지 못하는 장벽 |
| 바이어스를 거는 사람 | 사용자 — 확정 창에서 무엇을 통과시킬지 정해요 |

## 1. 순방향 — 지시가 안으로 (밖 › 안)

- 다이오드는 순방향 전압이 턴온 전압 V<sub>F</sub> (Si 로 약 0.6–0.7 V) 를 넘어야 전류가 흘러요. 문을 열려면 일정한 힘이 필요한 것과 비슷해요. Diode 의 순방향에도 문턱이 하나 있어요 — **넘기기 확정**: Claude 가 `dispatch` (일을 안쪽으로 넘기는 명령) 로 넘긴 지시를 사람이 확정 창에서 한 번 본 뒤에야 사내 LLM 에 들어가요 (AL-15).
- 순방향으로 흐르는 것은 지시뿐이에요. 지시를 넘긴 Claude 에게 돌아가는 것은 **고정된 한 줄** `{"sent": true, "job": "J-0001"}` 이에요 [실험 S05]. 사내 LLM 의 응답 · 로그 · 오류 글은 이 길로 되돌아가지 않아요 (AL-14).
- **화면의 표시도 문턱으로 읽어요.** 검사 (V<sub>bi</sub> 를 이루는 D1–D8) 를 모두 통과한 글은 `DIODE V>Vth 통과` — 문턱 전압을 넘어 흘러요. 하나라도 걸리면 `DIODE V<Vth 막힘 · D2 x2 @ask` — 문턱을 못 넘어 흐르지 않아요. 확정 창 · 훅 (정해진 때에 자동으로 도는 검문 프로그램) · `scan` 이 모두 같은 표시를 써요 (SPEC › SP-05).
- 왜 순방향은 열어도 되나요? Claude 가 아는 것은 봉인 글뿐이에요. 바깥의 정보가 안쪽으로 들어오는 것 자체는 새는 일이 아니에요. 다만 들어온 지시가 안쪽 일꾼을 마음대로 움직이게 만들 수는 있어요 (L-24). 그래서 문턱 (사람 확정) 과 안쪽 권한 (셸 명령마다 허락) 을 둬요.

## 2. 역방향 — 원자료는 막힌다 (안 › 밖)

### 2-1 역포화 전류 I<sub>s</sub> = 설계로 정한 누설

$$I = I_s\left[\exp\!\left(\frac{qV}{nkT}\right) - 1\right], \qquad I_s = qAn_i^2\left(\frac{D_p}{L_pN_D} + \frac{D_n}{L_nN_A}\right)$$

위 식은 다이오드에 전압 V 를 걸었을 때 흐르는 전류 I 를 나타내요. 거꾸로 걸면 (V 가 음수) 대괄호 안이 −1 에 가까워져서 전류가 거의 I<sub>s</sub> 하나만 남아요. 이 I<sub>s</sub> 가 "거꾸로 흐르는 아주 작은 전류" 예요.

- 역방향에서 다수 캐리어는 장벽에 막혀요. 장벽을 거꾸로 타고 내려가는 **소수 캐리어** 만 작은 전류 I<sub>s</sub> 를 만들어요. 역전압을 더 걸어도 거의 늘지 않아요.
- Diode 의 I<sub>s</sub> 는 **봉인 보고** 예요. 사내 LLM 이 원자료로 일한 결과를 정해진 양식 (`kind: "report"` — 상태 · 닫힌 숫자 칸 · 일반 말 요약 · 열린 질문) 으로만 쓰고, 검사기와 사람 확정을 지나야 바깥으로 가요. 양식에 코드 원문 · 로그 · 파일 이름 칸이 **아예 없어요**.
- I<sub>s</sub> ∝ n<sub>i</sub><sup>2</sup> ∝ exp(−E<sub>g</sub>/kT) — 밴드갭 (전자가 뛰어넘어야 하는 에너지 간격) 이 클수록 누설이 지수적으로 (아주 빠르게) 작아져요. Diode 에서 밴드갭에 해당하는 것은 **형식이 얼마나 닫혀 있나** 예요. 자유 글 칸을 줄이고 길이 상한 (펼친 글 8 KB [제안]) 을 두는 것이 밴드갭을 넓히는 일이에요.

### 2-2 생성 전류 = 공핍층 안에서 저절로 생기는 누설

$$I_{gen} = \frac{qn_iWA}{2\tau_0}$$

- 공핍층 안에서 열 때문에 저절로 생긴 전자-정공 쌍이 전기장에 휩쓸려 나가며 만드는 누설이에요. 공핍층의 부피 (W·A) 에 비례하고, 0 으로 만들 수 없어요.
- Diode 에서는 **방 안에서 Claude Code 가 스스로 만들어 붙이는 기계 정보** 가 이것이에요 [실험 S01 · T02]: Claude Code 판 · OS 와 판 · CPU 종류 · 세션 id · 사용자 해시 id · 작업 폴더 경로 · 날짜.
- 줄이는 법은 공핍층을 작게 하는 것이에요 — 방은 작고 중립적으로 둬요. 경로는 `D:\claude\room` (사용자 이름 · 사내 말이 없어요) 이고, 방 안에는 봉인 글과 답만 둬요. 이 누설이 있다는 사실은 보안 부서 설명에 적어요 ([kit/security-brief.md](../kit/security-brief.md)).

### 2-3 표면 누설과 보호막 (passivation)

- 실제 다이오드의 역방향 누설에는 접합 가장자리 · 표면을 따라 흐르는 **표면 누설** 이 더해져요. 산화막 같은 보호막으로 막아요.
- M0 에서 찾은 옆길 다섯이 표면 누설이에요. 접합 (검사기 · 확정 창) 을 지나지 않고 가장자리로 새요 — 그리고 방 설정 다섯이 보호막이에요. 보호막을 씌우기 전과 뒤를 같은 조건으로 쟀어요:

| 옆길 (표면 누설) | 보호막 전 | 보호막 (방 설정) | 보호막 뒤 |
|---|---|---|---|
| 방 위 폴더의 `CLAUDE.md` 내용 | 실림 [S01] | `claudeMdExcludes` | 없음 [S14] |
| 사용자 범위 `~/.claude/CLAUDE.md` 내용 | 실림 [S15] | `claudeMdExcludes` | 없음 [S14] |
| HOME 경로 (자동 메모리 자리 · Windows 에서는 사용자 이름) | 실림 [S01] | `autoMemoryEnabled: false` | 없음 [S13] |
| 대화형 auto 모드의 `safeguards` — HOME · 권한 규칙 · 신뢰 폴더 · git 상태 | 실림 [T01] | `permissions.defaultMode: "default"` | 없음 [T02] |
| 방 위 폴더가 git 저장소일 때 가지 이름 | 실림 [S02] | `D:\claude` 를 git 저장소로 만들지 않는다 | — |

- 보호막은 플러그인을 꺼도 방 설정으로 남아요. 접합 자체와 따로 동작하는 층이라는 점이 실제 보호막과 같아요.

## 3. 터널링 — 장벽이 얇으면 뜻이 새어 나간다

$$T \approx \exp(-2\kappa d), \qquad \kappa = \frac{\sqrt{2m^*(U-E)}}{\hbar}$$

위 식은 장벽을 뚫고 지나갈 확률 T 가 장벽 두께 d 가 커질수록 아주 빠르게 줄어든다는 뜻이에요.

- 장벽이 충분히 얇으면 캐리어는 장벽을 넘지 않고 **뚫고** 지나가요. 투과 확률은 장벽 두께 d 에 지수적으로 민감해요 (Zener 영역).
- Diode 에서 장벽 두께는 **추상화의 두께** 예요. 추상화 = 구체적인 내용을 덜어 내고 큰 틀만 남기는 일이에요. 이름을 `PH_K7Q2` 로 바꿨어도 brief (안쪽에 넘기는 일의 설명서) 가 너무 구체적이면 (공정 순서 · 수치 관계 · 맥락이 그대로면) Claude 가 원래 단어를 맞혀 버릴 수 있어요 — 장벽을 넘지 않고 뜻이 새는 재식별 (가려 둔 것을 다시 알아내기) 이에요 (L-05).
- 그래서 가린 원자료를 보내지 않고 **일의 모양** 만 보내요 — 장벽을 두껍게 하는 거예요. 조금만 더 일반화해도 투과 확률은 지수적으로 줄어든다는 것이 이 비유의 요점이에요.
- 터널링 탐지기: Claude 의 답에 보낸 적 없는 사전 단어가 나오면 경보를 울리고 그 주제를 멈춰요 (U2 · 역유입).

## 4. 항복 — 정격을 넘기면 막는 성질을 잃는다

$$M = \frac{1}{1-(V_R/V_{BR})^{n}}$$

위 식에서 역전압 V<sub>R</sub> 이 항복 전압 V<sub>BR</sub> 에 가까워지면 분모가 0 에 가까워져서 M 이 끝없이 커져요.

- 역전압이 항복 전압 V<sub>BR</sub> 에 다가가면 애벌랜치 증배 M 이 발산하고 (끝없이 커지고), 역전류가 폭증해요. 소자는 막는 성질을 잃어요. 한 번 시작되면 연쇄적으로 커져요.
- Diode 의 항복은 **작정한 우회** 예요: 같은 계정의 사내 LLM 이 셸 (명령 입력 창) 로 Claude 를 직접 부르기 (R1) · 사용자가 플러그인을 끄기 (R25 — 대조 실험에서 플러그인 없이는 원자료가 그대로 실렸어요 [S12]) · 확정 창을 읽지 않고 누르기 (R5) · 웹 Claude 에 직접 붙여 넣기.
- 실제 소자는 **가드링 · 필드 플레이트** 로 가장자리 전계 (전기의 세기) 를 풀어 V<sub>BR</sub> 을 올려요. Diode 의 가드링은 여러 겹이에요: 플러그인 훅 (막는 쪽으로 실패 — 훅이 죽으면 막혔어요 [S09]) · 방 권한 설정 (훅 없이도 방 밖 읽기가 막혔어요 [S16]) · opencode 의 셸 허락 · 회사 IT 의 관리형 설정 · 회사 망 쪽 확인.
- 그리고 **정격 안에서만 써요**. 데이터시트의 V<sub>RRM</sub> (되풀이해서 걸어도 되는 최대 역전압) 을 넘겨 쓰지 않듯, 보안 부서가 허용 범위를 정하기 전까지 실데이터는 0 이에요 (AL-10).

## 5. 역회복 — 저장된 전하를 빼고 끈다

- 순방향에서 역방향으로 바꿀 때, 접합 근처에 쌓여 있던 소수 캐리어 전하 Q<sub>rr</sub> 이 빠질 때까지 잠깐 역전류가 흘러요 (t<sub>rr</sub>).
- Diode 에 쌓이는 전하는 **가명 표** (`PH_K7Q2` ↔ 진짜 단어, 진짜 이름과 가짜 이름표를 짝지은 표) 예요. 허브가 세션 동안 메모리에만 쥐고 있다가 세션이 끝나면 사라져요. 디스크에 쓰지 않으므로 끈 뒤에 남는 Q<sub>rr</sub> 이 없어요 (Q6 · W-05).

## 6. 온도 특성 — 많이 쓸수록 누설이 는다

- I<sub>s</sub> 는 온도에 지수적으로 민감해요 (경험칙으로 약 10 °C 마다 두 배).
- Diode 의 온도는 **쓴 양** 이에요. 자문 (Claude 에게 물어보기) 하나하나는 작아도 같은 주제로 여러 번 보내면 모은 그림이 원래 모습에 가까워져요 (모자이크 · L-05 — 작은 조각을 모으면 큰 그림이 되는 것). 열을 식히는 설계에서 누적을 보듯 여기서도 누계를 봐요 — 주제별 누계 · 하루 상한 · 월 한도 · 확정 창의 이번 달 % (statusLine 으로 받은 실제 사용량 [실험 T01]).

## 7. 이상 다이오드 · 실제 다이오드 · 광 아이솔레이터

| | 역방향 누설 | Diode 와의 관계 |
|---|---|---|
| 이상 다이오드 | 0 | 없다 — 어떤 소프트웨어도 이렇게 되지 않는다 |
| 광 아이솔레이터 · 하드웨어 데이터 다이오드 | 되돌아오는 물리적 길이 없다 | **Diode 는 이것이 아니다** (R18) — 같은 보증을 주지 않는다 |
| 실제 PN 다이오드 | I<sub>s</sub> + 생성 + 표면 누설 · 항복 있음 | **Diode 는 이것이다** — 그래서 데이터시트를 공개한다 |

## 10. 비유의 한계

- 실제 다이오드의 순방향 전류는 전자와 정공이 서로 반대 쪽에서 들어와 흘러요. Diode 의 순방향은 지시 한 가지만 흘러요 — 순방향에서 원자료가 바깥으로 따라 나가지 않아요.
- 다이오드는 수동 소자예요. 스스로 판단하지 않고 물리 법칙대로만 움직여요. Diode 에는 **사람** 이라는 능동 판단이 접합 한가운데 있어요 — 가장 강한 장벽이자 가장 약한 고리예요.
- 식의 지수 · "10 °C 마다 두 배" 같은 수치는 감을 잡기 위한 비유예요. Diode 의 실제 성능은 8 의 측정값과 리스크 대장으로만 말해요.
