# Diode 청사진 — PN 접합으로 읽기

- **누가 읽나**: 반도체 소자를 학부 수준으로 배운 사람. 설계의 정본은 [PLAN.md](PLAN.md) 이고, 이 문서는 그 설계를 PN 접합 다이오드의 언어로 다시 읽는다.
- **측정값**: [실험] 표시는 M0 리눅스판 ([kit/results-linux.md](../kit/results-linux.md) · 2026-11-05 · Claude Code 2.1.318 · 가짜 서버 · 합성 자료) 에서 본 것이다. 식과 비율은 **비유** 이고 측정값이 아니다.
- **한 줄**: Diode 는 회사 안 (사내 LLM · 원자료) 과 회사 밖 (Claude) 사이의 접합이다. 순방향 (밖 › 안 · 지시) 은 흐르고, 역방향 (안 › 밖 · 원자료) 은 막는다. 역방향으로 흐르는 것은 **설계로 정해 둔 작은 누설 — 사람이 확정한 봉인 보고** 뿐이다.

## 0. 회로 기호와 단자

```text
        애노드 (p)                    접합 · 공핍층                    캐소드 (n)
   바깥: Claude CLI 세션   ───────────▶|───────────   안쪽: 사내 LLM (opencode) · 원자료
                          깨끗한 방 · 허브 · 검사기 · 확정 창 · 기록

   순방향 (애노드 → 캐소드): Claude 의 지시가 안쪽으로 — 흐른다
   역방향 (캐소드 → 애노드): 원자료가 바깥으로 — 막힌다 (작은 의도된 누설만)
```

| 소자 | Diode |
|---|---|
| n 영역의 다수 캐리어 (전자) | **원자료** — 안쪽에 넘친다 · 바깥으로 넘어가면 안 된다 |
| n 영역의 소수 캐리어 (정공) | 원자료가 아닌 작은 정보 — 일반 말로 다시 쓴 **봉인 보고** |
| 공핍층 (자유 캐리어가 없는 영역) | **깨끗한 방** (`D:\claude\room`) 과 허브 — 원자료가 하나도 없는 영역 |
| 내부 전위 장벽 V<sub>bi</sub> | 결정적 검사기 D1–D8 · 닫힌 형식 (brief) — 다수 캐리어가 넘지 못하는 장벽 |
| 바이어스를 거는 사람 | 사용자 — 확정 창에서 무엇을 통과시킬지 정한다 |

## 1. 순방향 — 지시가 안으로 (밖 › 안)

- 다이오드는 순방향 전압이 턴온 전압 V<sub>F</sub> (Si 로 약 0.6–0.7 V) 를 넘어야 전류가 흐른다. Diode 의 순방향에도 문턱이 하나 있다 — **넘기기 확정**: Claude 가 `dispatch` 로 넘긴 지시를 사람이 확정 창에서 한 번 본 뒤에 사내 LLM 에 들어간다 (AL-15).
- 순방향으로 흐르는 것은 지시뿐이다. 지시를 넘긴 Claude 에게 돌아가는 것은 **고정된 한 줄** `{"sent": true, "job": "J-0001"}` 이다 [실험 S05]. 사내 LLM 의 응답 · 로그 · 오류 글은 이 길로 되돌아가지 않는다 (AL-14).
- 왜 순방향은 열어도 되나: Claude 가 아는 것은 봉인 글뿐이다. 바깥의 정보가 안쪽으로 들어오는 것 자체는 새는 일이 아니다. 다만 들어온 지시가 안쪽 일꾼을 조종할 수는 있으므로 (L-24), 문턱 (사람 확정) 과 안쪽 권한 (셸 명령마다 허락) 을 둔다.

## 2. 역방향 — 원자료는 막힌다 (안 › 밖)

### 2-1 역포화 전류 I<sub>s</sub> = 설계로 정한 누설

$$I = I_s\left[\exp\!\left(\frac{qV}{nkT}\right) - 1\right], \qquad I_s = qAn_i^2\left(\frac{D_p}{L_pN_D} + \frac{D_n}{L_nN_A}\right)$$

- 역방향에서 다수 캐리어는 장벽에 막히고, 장벽을 거꾸로 타고 내려가는 **소수 캐리어** 만 작은 전류 I<sub>s</sub> 를 만든다. 역전압을 더 걸어도 거의 늘지 않는다.
- Diode 의 I<sub>s</sub> 는 **봉인 보고** 다. 사내 LLM 이 원자료로 일한 결과를 정해진 양식 (`kind: "report"` — 상태 · 닫힌 숫자 칸 · 일반 말 요약 · 열린 질문) 으로만 쓰고, 검사기와 사람 확정을 지나야 바깥으로 간다. 양식에 코드 원문 · 로그 · 파일 이름 칸이 **아예 없다**.
- I<sub>s</sub> ∝ n<sub>i</sub><sup>2</sup> ∝ exp(−E<sub>g</sub>/kT) — 밴드갭이 클수록 누설이 지수적으로 작다. Diode 에서 밴드갭에 해당하는 것은 **형식이 얼마나 닫혀 있나** 다. 자유 글 칸을 줄이고 길이 상한 (펼친 글 8 KB [제안]) 을 두는 것이 밴드갭을 넓히는 일이다.

### 2-2 생성 전류 = 공핍층 안에서 저절로 생기는 누설

$$I_{gen} = \frac{qn_iWA}{2\tau_0}$$

- 공핍층 안에서 열로 생성된 전자-정공 쌍이 장에 휩쓸려 나가며 만드는 누설이다. 공핍층의 부피 (W·A) 에 비례하고, 0 으로 만들 수 없다.
- Diode 에서는 **방 안에서 Claude Code 가 스스로 만들어 붙이는 기계 정보** 가 이것이다 [실험 S01 · T02]: Claude Code 판 · OS 와 판 · CPU 종류 · 세션 id · 사용자 해시 id · 작업 폴더 경로 · 날짜.
- 줄이는 법은 공핍층을 작게 하는 것 — 방은 작고 중립적으로 둔다. 경로는 `D:\claude\room` (사용자 이름 · 사내 말이 없다), 방 안에는 봉인 글과 답만 둔다. 이 누설이 있다는 사실은 보안 부서 설명에 적는다 ([kit/security-brief.md](../kit/security-brief.md)).

### 2-3 표면 누설과 보호막 (passivation)

- 실제 다이오드의 역방향 누설에는 접합 가장자리 · 표면 상태를 따라 흐르는 **표면 누설** 이 더해진다. 산화막 등 보호막으로 막는다.
- M0 에서 찾은 옆길 다섯이 표면 누설이다. 접합 (검사기 · 확정 창) 을 지나지 않고 가장자리로 샌다 — 그리고 방 설정 다섯이 보호막이다. 보호막 전후를 같은 조건으로 쟀다:

| 옆길 (표면 누설) | 보호막 전 | 보호막 (방 설정) | 보호막 뒤 |
|---|---|---|---|
| 방 위 폴더의 `CLAUDE.md` 내용 | 실림 [S01] | `claudeMdExcludes` | 없음 [S14] |
| 사용자 범위 `~/.claude/CLAUDE.md` 내용 | 실림 [S15] | `claudeMdExcludes` | 없음 [S14] |
| HOME 경로 (자동 메모리 자리 · Windows 에서는 사용자 이름) | 실림 [S01] | `autoMemoryEnabled: false` | 없음 [S13] |
| 대화형 auto 모드의 `safeguards` — HOME · 권한 규칙 · 신뢰 폴더 · git 상태 | 실림 [T01] | `permissions.defaultMode: "default"` | 없음 [T02] |
| 방 위 폴더가 git 저장소일 때 가지 이름 | 실림 [S02] | `D:\claude` 를 git 저장소로 만들지 않는다 | — |

- 보호막은 플러그인을 꺼도 방 설정으로 남는다. 접합 자체와 별개로 동작하는 층이라는 점이 실제 보호막과 같다.

## 3. 터널링 — 장벽이 얇으면 뜻이 새어 나간다

$$T \approx \exp(-2\kappa d), \qquad \kappa = \frac{\sqrt{2m^*(U-E)}}{\hbar}$$

- 장벽이 충분히 얇으면 캐리어는 장벽을 넘지 않고 **뚫고** 지나간다. 투과 확률은 장벽 두께 d 에 지수적으로 민감하다 (Zener 영역).
- Diode 에서 장벽 두께는 **추상화의 두께** 다. 이름을 `PH_K7Q2` 로 바꿨어도 brief 가 너무 구체적이면 (공정 순서 · 수치 관계 · 맥락이 그대로면) Claude 가 원래 단어를 맞혀 버릴 수 있다 — 장벽을 넘지 않고 뜻이 새는 재식별이다 (L-05).
- 그래서 가린 원자료를 보내지 않고 **일의 모양** 만 보낸다 — 장벽을 두껍게. 조금만 더 일반화해도 투과 확률은 지수적으로 준다는 것이 이 비유의 요점이다.
- 터널링 탐지기: Claude 의 답에 보낸 적 없는 사전 단어가 나오면 경보를 울리고 그 주제를 멈춘다 (U2 · 역유입).

## 4. 항복 — 정격을 넘기면 막는 성질을 잃는다

$$M = \frac{1}{1-(V_R/V_{BR})^{n}}$$

- 역전압이 항복 전압 V<sub>BR</sub> 에 다가가면 애벌랜치 증배 M 이 발산하고, 역전류가 폭증한다. 소자는 막는 성질을 잃는다. 한 번 시작되면 연쇄적으로 커진다.
- Diode 의 항복은 **작정한 우회** 다: 같은 계정의 사내 LLM 이 셸로 Claude 를 직접 부르기 (R1) · 사용자가 플러그인을 끄기 (R25 — 대조 실험에서 플러그인 없이는 원자료가 그대로 실렸다 [S12]) · 확정 창을 읽지 않고 누르기 (R5) · 웹 Claude 에 직접 붙여 넣기.
- 실제 소자는 **가드링 · 필드 플레이트** 로 가장자리 전계를 풀어 V<sub>BR</sub> 을 올린다. Diode 의 가드링은 겹이다: 플러그인 훅 (막는 쪽으로 실패 — 훅이 죽으면 막혔다 [S09]) · 방 권한 설정 (훅 없이도 방 밖 읽기가 막혔다 [S16]) · opencode 의 셸 허락 · 회사 IT 의 관리형 설정 · 회사 망 쪽 확인.
- 그리고 **정격 안에서만 쓴다**. 데이터시트의 V<sub>RRM</sub> 을 넘겨 쓰지 않듯, 보안 부서가 허용 범위를 정하기 전까지 실데이터는 0 이다 (AL-10).

## 5. 역회복 — 저장된 전하를 빼고 끈다

- 순방향에서 역방향으로 바꿀 때, 접합 근처에 저장된 소수 캐리어 전하 Q<sub>rr</sub> 이 빠질 때까지 잠깐 역전류가 흐른다 (t<sub>rr</sub>).
- Diode 에 저장되는 전하는 **가명 표** (`PH_K7Q2` ↔ 진짜 단어) 다. 허브가 세션 동안 메모리에만 쥐고, 세션이 끝나면 사라진다. 디스크에 쓰지 않으므로 끈 뒤에 남는 Q<sub>rr</sub> 이 없다 (Q6 · W-05).

## 6. 온도 특성 — 많이 쓸수록 누설이 는다

- I<sub>s</sub> 는 온도에 지수적으로 민감하다 (경험칙으로 약 10 °C 마다 두 배).
- Diode 의 온도는 **쓴 양** 이다. 자문 하나하나는 작아도 같은 주제로 여러 번 보내면 모은 그림이 원래 모습에 가까워진다 (모자이크 · L-05). 방열 설계처럼 누계를 본다 — 주제별 누계 · 하루 상한 · 월 한도 · 확정 창의 이번 달 % (statusLine 으로 받은 실제 사용량 [실험 T01]).

## 7. 이상 다이오드 · 실제 다이오드 · 광 아이솔레이터

| | 역방향 누설 | Diode 와의 관계 |
|---|---|---|
| 이상 다이오드 | 0 | 없다 — 어떤 소프트웨어도 이렇게 되지 않는다 |
| 광 아이솔레이터 · 하드웨어 데이터 다이오드 | 되돌아오는 물리적 길이 없다 | **Diode 는 이것이 아니다** (R18) — 같은 보증을 주지 않는다 |

## 10. 비유의 한계

- 실제 다이오드의 순방향 전류는 전자와 정공이 서로 반대로 주입되어 흐른다. Diode 의 순방향은 지시 한 가지만 흐른다 — 순방향에서 원자료가 바깥으로 따라 나가지 않는다.
- 다이오드는 수동 소자다. Diode 에는 **사람** 이라는 능동 판단이 접합 한가운데 있다 — 가장 강한 장벽이자 가장 약한 고리다.
- 식의 지수 · "10 °C 마다 두 배" 같은 수치는 직관을 위한 비유다. Diode 의 실제 성능은 8 의 측정값과 리스크 대장으로만 말한다.
