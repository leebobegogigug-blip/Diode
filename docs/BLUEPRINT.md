# Diode 청사진 — PN 접합으로 읽기

- **누가 읽나**: 반도체 소자를 대학에서 조금 배운 사람이 읽으면 가장 잘 이해할 수 있습니다. 몰라도 읽을 수 있도록 낱말마다 풀어 두었습니다. 설계의 공식 기준 문서는 [PLAN.md](PLAN.md)이고, 이 문서는 그 설계를 PN 접합 다이오드(전기를 한쪽으로만 흐르게 하는 부품)의 용어로 다시 풀이합니다.
- **측정값**: [실험] 표시는 M0 리눅스판([kit/results-linux.md](../kit/results-linux.md) · 2026-11-05 · Claude Code 2.1.318 · 모의 서버 · synthetic data(가상 자료))에서 직접 확인한 값입니다. 식과 비율은 **비유**이며 측정값이 아닙니다.
- **한 줄**: Diode는 회사 내부(사내 LLM · 원자료)와 회사 외부(Claude) 사이의 접합입니다. 순방향(외부 › 내부 · 지시)은 흐르고, 역방향(내부 › 외부 · 원자료)은 막습니다. 역방향으로 흐르는 것은 **설계로 정해 둔 작은 누설 — 사람이 승인한 봉인 보고**(9판부터는 가려서 승인한 파일 묶음도)뿐입니다.
- **낱말 풀이**: 사내 LLM = 회사 내부에서 실행되는 인공지능. 원자료 = 회사 내부에 있는 실제 자료. 봉인 보고 = 일반적인 말로 다시 쓴, 외부로 나가도 되는 짧은 보고서.

## 0. 회로 기호와 단자

```text
        애노드 (p)                    접합 · 공핍층                    캐소드 (n)
   외부: Claude CLI 세션   ───────────▶|───────────   내부: 사내 LLM (opencode) · 원자료
                          깨끗한 방 · hub · 검사 · 승인 창 · 기록

   순방향 (애노드 → 캐소드): Claude의 지시가 내부로 — 흐릅니다
   역방향 (캐소드 → 애노드): 원자료가 외부로 — 막힙니다 (작은 의도된 누설만)
```

위 그림은 다이오드 회로 기호입니다. 다이오드는 전기가 한쪽 방향으로만 잘 흐르는 부품이고, Diode는 정보에 대해 같은 일을 합니다. 아래 표는 반도체 낱말이 Diode의 무엇에 해당하는지 짝지어 둔 것입니다.

| 소자 | Diode |
|---|---|
| n 영역의 다수 캐리어(전자) | **원자료** — 내부에 넘쳐납니다 · 외부로 넘어가면 안 됩니다 |
| n 영역의 소수 캐리어(정공) | 원자료가 아닌 작은 정보 — 일반적인 말로 다시 쓴 **봉인 보고** |
| 공핍층(자유 캐리어가 없는 영역) | **깨끗한 방**(`D:\claude\room`)과 hub — 원자료가 하나도 없는 영역 |
| 내부 전위 장벽 V<sub>bi</sub> | 결정적 검사기 D1–D8 · 닫힌 형식(brief) — 다수 캐리어가 넘지 못하는 장벽 |
| 바이어스를 거는 사람 | 사용자 — 승인 창(confirm window)에서 무엇을 통과시킬지 정합니다 |

## 1. 순방향 — 지시가 안으로 (밖 › 안)

- 다이오드는 순방향 전압이 턴온 전압 V<sub>F</sub>(Si로 약 0.6–0.7 V)를 넘어야 전류가 흐릅니다. 문을 열려면 일정한 힘이 필요한 것과 비슷합니다. Diode의 순방향에도 문턱이 하나 있습니다 — **넘기기 승인**: Claude가 `dispatch`(일을 내부로 넘기는 명령)로 넘긴 지시를 사람이 승인 창에서 한 번 확인한 뒤에야 사내 LLM에 들어갑니다(AL-15).
- 순방향으로 흐르는 것은 지시뿐입니다. 지시를 넘긴 Claude에게 돌아가는 것은 **고정된 한 줄** `{"sent": true, "job": "J-0001"}`입니다 [실험 S05]. 사내 LLM의 응답 · 로그 · 오류 문구는 이 경로로 되돌아가지 않습니다(AL-14).
- **화면의 표시도 문턱으로 읽습니다.** 검사(V<sub>bi</sub>를 이루는 D1–D8)를 모두 통과한 글은 `DIODE V>Vth 통과` — 문턱 전압을 넘어 흐릅니다. 하나라도 걸리면 `DIODE V<Vth 막힘 · D2 x2 @ask` — 문턱을 넘지 못해 흐르지 않습니다. 승인 창 · hook(정해진 시점에 자동으로 실행되는 검문 프로그램) · `scan`이 모두 같은 표시를 사용합니다(SPEC › SP-05).
- 왜 순방향은 열어도 됩니까? Claude가 아는 것은 봉인 글뿐입니다. 외부의 정보가 내부로 들어오는 것 자체는 유출이 아닙니다. 다만 들어온 지시가 내부 에이전트를 마음대로 움직이게 만들 수는 있습니다(L-24). 그래서 문턱(사람의 승인)과 내부 권한(셸 명령마다 허락)을 둡니다.

## 2. 역방향 — 원자료는 막힌다 (안 › 밖)

### 2-1 역포화 전류 I<sub>s</sub> = 설계로 정한 누설

$$I = I_s\left[\exp\!\left(\frac{qV}{nkT}\right) - 1\right], \qquad I_s = qAn_i^2\left(\frac{D_p}{L_pN_D} + \frac{D_n}{L_nN_A}\right)$$

위 식은 다이오드에 전압 V를 걸었을 때 흐르는 전류 I를 나타냅니다. 거꾸로 걸면(V가 음수) 대괄호 안이 −1에 가까워져서 전류가 거의 I<sub>s</sub> 하나만 남습니다. 이 I<sub>s</sub>가 "거꾸로 흐르는 아주 작은 전류"입니다.

- 역방향에서 다수 캐리어는 장벽에 막힙니다. 장벽을 거꾸로 타고 내려가는 **소수 캐리어**만 작은 전류 I<sub>s</sub>를 만듭니다. 역전압을 더 걸어도 거의 늘지 않습니다.
- Diode의 I<sub>s</sub>는 **봉인 보고**입니다. 사내 LLM이 원자료로 일한 결과를 정해진 양식(`kind: "report"` — 상태 · 닫힌 숫자 필드 · 일반적인 말 요약 · 열린 질문)으로만 작성하고, 검사기와 사람의 승인을 거쳐야 외부로 나갑니다. 양식에 코드 원문 · 로그 · 파일 이름 필드가 **아예 없습니다**.
- 9판부터 누설은 **한 갈래**가 더 있습니다 — **가린 파일 묶음**입니다. 코드 · 표 · 문서의 이름과 수치를 가명 토큰으로 가리고(가명 금고), 남은 것이 없는지 잔여 검사(R1–R6)로 확인한 뒤, 사람이 파일마다 열어 보고 승인해야 나갑니다([명세 › SP-20](SPEC.md#sp-20-가린-왕복-masked-round-trip--9판)). 봉인 보고처럼 닫힌 양식이 아니므로(코드의 구조 · 표의 형식은 그대로 나갑니다) 그만큼 누설이 큽니다. 그래서 한 번에 보내는 크기와 한 작업 묶음 전체의 전송량에 상한을 둡니다.
- I<sub>s</sub> ∝ n<sub>i</sub><sup>2</sup> ∝ exp(−E<sub>g</sub>/kT) — 밴드갭(전자가 뛰어넘어야 하는 에너지 간격)이 클수록 누설이 지수적으로(아주 빠르게) 작아집니다. Diode에서 밴드갭에 해당하는 것은 **형식이 얼마나 닫혀 있는가**입니다. 자유 글 필드를 줄이고 길이 상한(펼친 글 8 KB [제안])을 두는 것이 밴드갭을 넓히는 일입니다.

### 2-2 생성 전류 = 공핍층 안에서 저절로 생기는 누설

$$I_{gen} = \frac{qn_iWA}{2\tau_0}$$

- 공핍층 안에서 열 때문에 자동으로 생긴 전자-정공 쌍이 전기장에 휩쓸려 나가며 만드는 누설입니다. 공핍층의 부피(W·A)에 비례하며, 0으로 만들 수 없습니다.
- Diode에서는 **방 안에서 Claude Code가 스스로 만들어 붙이는 기계 정보**가 이에 해당합니다 [실험 S01 · T02]: Claude Code 버전 · OS 버전 · CPU 종류 · 세션 id · 사용자 해시 id · 작업 폴더 경로 · 날짜.
- 줄이는 방법은 공핍층을 작게 하는 것입니다 — 방은 작고 중립적으로 둡니다. 경로는 `D:\claude\room`(사용자 이름 · 사내 단어가 없습니다)이고, 방 안에는 봉인 글과 답만 둡니다. 이 누설이 있다는 사실은 보안 부서 설명에 적어 둡니다([kit/security-brief.md](../kit/security-brief.md)).

### 2-3 표면 누설과 보호막 (passivation)

- 실제 다이오드의 역방향 누설에는 접합 가장자리 · 표면을 따라 흐르는 **표면 누설**이 더해집니다. 산화막 같은 보호막으로 막습니다.
- M0에서 찾은 옆길 다섯이 표면 누설입니다. 접합(검사기 · 승인 창)을 거치지 않고 가장자리로 샙니다. 그리고 방 설정 다섯이 보호막입니다. 보호막을 씌우기 전과 뒤를 같은 조건으로 측정했습니다:

| 옆길(표면 누설) | 보호막 전 | 보호막(방 설정) | 보호막 뒤 |
|---|---|---|---|
| 방 상위 폴더의 `CLAUDE.md` 내용 | 포함됨 [S01] | `claudeMdExcludes` | 없음 [S14] |
| 사용자 범위 `~/.claude/CLAUDE.md` 내용 | 포함됨 [S15] | `claudeMdExcludes` | 없음 [S14] |
| HOME 경로(자동 메모리 위치 · Windows에서는 사용자 이름) | 포함됨 [S01] | `autoMemoryEnabled: false` | 없음 [S13] |
| 대화형 auto 모드의 `safeguards` — HOME · 권한 규칙 · 신뢰 폴더 · git 상태 | 포함됨 [T01] | `permissions.defaultMode: "default"` | 없음 [T02] |
| 방 상위 폴더가 git 저장소일 때 branch 이름 | 포함됨 [S02] | `D:\claude`를 git 저장소로 만들지 않음 | — |

- 보호막은 플러그인을 꺼도 방 설정으로 남습니다. 접합 자체와 별도로 동작하는 층이라는 점이 실제 보호막과 같습니다.

## 3. 터널링 — 장벽이 얇으면 뜻이 새어 나간다

$$T \approx \exp(-2\kappa d), \qquad \kappa = \frac{\sqrt{2m^*(U-E)}}{\hbar}$$

위 식은 장벽을 뚫고 지나갈 확률 T가 장벽 두께 d가 커질수록 아주 빠르게 줄어든다는 뜻입니다.

- 장벽이 충분히 얇으면 캐리어는 장벽을 넘지 않고 **뚫고** 지나갑니다. 투과 확률은 장벽 두께 d에 지수적으로 민감합니다(Zener 영역).
- Diode에서 장벽 두께는 **추상화의 두께**입니다. 추상화 = 구체적인 내용을 덜어 내고 큰 틀만 남기는 일입니다. 이름을 `PH_K7Q2`로 바꿨어도 brief(내부에 넘기는 일의 설명서)가 너무 구체적이면(공정 순서 · 수치 관계 · 맥락이 그대로면) Claude가 원래 단어를 맞혀 버릴 수 있습니다 — 장벽을 넘지 않고 뜻이 새는 재식별(가려 둔 것을 다시 알아내기)입니다(L-05).
- 그래서 가린 원자료를 보내지 않고 **일의 모양**만 보냅니다. 이는 장벽을 두껍게 하는 일입니다. 조금만 더 일반화해도 투과 확률은 지수적으로 줄어든다는 것이 이 비유의 요점입니다.
- 터널링 탐지기: Claude의 답에 보낸 적 없는 사전 단어가 나오면 경보를 울리고 그 주제를 멈춥니다(U2 · 역유입).

## 4. 항복 — 정격을 넘기면 막는 성질을 잃는다

$$M = \frac{1}{1-(V_R/V_{BR})^{n}}$$

위 식에서 역전압 V<sub>R</sub>이 항복 전압 V<sub>BR</sub>에 가까워지면 분모가 0에 가까워져서 M이 끝없이 커집니다.

- 역전압이 항복 전압 V<sub>BR</sub>에 다가가면 애벌랜치 증배 M이 발산하고(끝없이 커지고), 역전류가 폭증합니다. 소자는 막는 성질을 잃습니다. 한 번 시작되면 연쇄적으로 커집니다.
- Diode의 항복은 **작정한 우회**입니다: 같은 계정의 사내 LLM이 셸(명령 입력 창)로 Claude를 직접 호출하기(R1) · 사용자가 플러그인을 끄기(R25 — 대조 실험에서 플러그인 없이는 원자료가 그대로 포함되었습니다 [S12]) · 승인 창을 읽지 않고 누르기(R5) · 웹 Claude에 직접 붙여넣기.
- 실제 소자는 **가드링 · 필드 플레이트**로 가장자리 전계(전기의 세기)를 풀어 V<sub>BR</sub>을 올립니다. Diode의 가드링은 여러 겹입니다: 플러그인 hook(막는 쪽으로 실패 — hook이 죽으면 막혔습니다 [S09]) · 방 권한 설정(hook 없이도 방 밖 읽기가 막혔습니다 [S16]) · opencode의 셸 허락 · 회사 IT의 관리형 설정 · 회사 망 쪽 확인.
- 그리고 **정격 안에서만 사용합니다**. 데이터시트의 V<sub>RRM</sub>(되풀이해서 걸어도 되는 최대 역전압)을 넘겨서 사용하지 않듯, 보안 부서가 허용 범위를 정하기 전까지 real data(실데이터)는 0입니다(AL-10).

## 5. 역회복 — 저장된 전하를 빼고 끈다

- 순방향에서 역방향으로 바꿀 때, 접합 근처에 쌓여 있던 소수 캐리어 전하 Q<sub>rr</sub>이 빠질 때까지 잠깐 역전류가 흐릅니다(t<sub>rr</sub>).
- Diode에 쌓이는 전하는 **가명 표**(`PH_K7Q2` ↔ 실제 단어, 실제 이름과 가명 토큰을 짝지은 표)입니다. hub가 세션 동안 메모리에만 보관하다가 세션이 끝나면 사라집니다. 보고의 가명 표는 디스크에 쓰지 않으므로 끈 뒤에 남는 Q<sub>rr</sub>이 없습니다(Q6 · W-05). 예외는 가린 파일 묶음의 **금고** 하나입니다 — 작업 묶음이 열려 있는 동안 Windows DPAPI로 암호화해서 디스크에 두고, 묶음을 닫으면 지웁니다(W-05 · SP-20). 닫기 전까지는 이 전하가 디스크에 남아 있으므로, 그 파일이 동기화 · 백업 대상인지 확인하세요.

## 6. 온도 특성 — 많이 쓸수록 누설이 는다

- I<sub>s</sub>는 온도에 지수적으로 민감합니다(경험칙으로 약 10 °C마다 두 배).
- Diode의 온도는 **사용량**입니다. 자문(Claude에게 물어보기) 하나하나는 작아도 같은 주제로 여러 번 보내면 모은 그림이 원래 모습에 가까워집니다(모자이크 · L-05 — 작은 조각을 모으면 큰 그림이 되는 것). 열을 식히는 설계에서 누적을 확인하듯 여기서도 누계를 확인합니다 — 주제별 누계 · 하루 상한 · 월 한도 · 승인 창의 이번 달 %(statusLine으로 받은 실제 사용량 [실험 T01]).

## 7. 이상 다이오드 · 실제 다이오드 · 광 아이솔레이터

| | 역방향 누설 | Diode와의 관계 |
|---|---|---|
| 이상 다이오드 | 0 | 없습니다 — 어떤 소프트웨어도 이렇게 되지 않습니다 |
| 광 아이솔레이터 · 하드웨어 데이터 다이오드 | 되돌아오는 물리적 경로 없음 | **Diode는 이것이 아닙니다**(R18) — 같은 보증을 주지 않습니다 |

## 10. 비유의 한계

- 실제 다이오드의 순방향 전류는 전자와 정공이 서로 반대쪽에서 들어와 흐릅니다. Diode의 순방향은 지시 한 가지만 흐릅니다 — 순방향에서 원자료가 외부로 따라 나가지 않습니다.
- 다이오드는 수동 소자입니다. 스스로 판단하지 않고 물리 법칙대로만 움직입니다. Diode에는 **사람**이라는 능동 판단이 접합 한가운데 있습니다 — 가장 강한 장벽이자 가장 약한 고리입니다.
- 식의 지수 · "10 °C마다 두 배" 같은 수치는 이해를 돕기 위한 비유입니다. Diode의 실제 성능은 8절(데이터시트)의 측정값과 리스크 대장으로만 설명합니다.
