# Diode 사내 마무리 — 공개 저장소와 사내 작업의 경계

이 문서는 사내 Claude 가 이 저장소를 마무리할 때 지킬 경계를 못박아 둔 거예요. 아래 "사내에서 할 일 - 순서" 가 점검표예요 (T16). 사내 Claude = 회사 안에서 쓰는 Claude. 출처는 [기획서 › 07 사내 마무리](PLAN.md#사내-마무리--사내-claude-가-최종-검토-q5) 와 [R17](PLAN.md#11-리스크-대장) 이다.

## 왜 나누나

이 저장소는 공개예요 ([규칙 › W-12](../RULES.md#w-12-공개-저장소다)). 누구나 볼 수 있으니 사내 이름을 쓸 수 없고, 사내 TUI (글자로 된 화면 프로그램) 도 여기서는 볼 수 없어요. 그래서 일반 부분은 여기서 합성 자료 (지어낸 자료) 로 만들고, 사내에서만 할 수 있는 부분은 사내 Claude 가 사내 PC 에서 마무리해요.

## 경계

| 여기서 (공개 저장소 · 합성 자료) | 사내에서 (사내 Claude · 사내 PC) |
|---|---|
| 다이오드 본체 · 검사기 · 확정 창 · 건네기 `clipboard` · `room` · 방 프로필 · 안전벨트 · 어댑터 **계약** · 가짜 TUI 로 계약 테스트 | 사내 TUI 어댑터 구현 · KIT-1 · KIT-2 를 사내 PC · 사내 TUI 판으로 다시 · 사내 모델 이름 · 사전 · 정규식 설정 · 사내 PC 에서 전체 테스트 · 코드 최종 검토 |

## 어댑터 계약 [제안]

- 어댑터 = 사내 TUI 와 Diode 를 이어 주는 연결 부품이에요. 계약 = 그 부품이 꼭 갖춰야 할 함수들의 약속이에요.
- `name` · `check() → 결과 (effort 를 받는지 포함)` · `put(id, sealed_text, route)` · `get(id) → 답 또는 없음`.
- `route` 는 모델 · effort (얼마나 깊이 생각하게 할지) 두 값뿐이에요. 어댑터는 봉인된 글만 받아요 — 원문 · 가명 표 (진짜 이름과 가짜 이름표를 짝지은 표) 에 닿는 인자가 없어요.
- 계약 테스트를 통과해야 설정에서 고를 수 있어요. 계약을 확정하는 곳은 건네기 작업 (T11) 이에요.

## 사내 이름은 공개 저장소로 돌아오지 않는다

- 사내 이름이 들어간 것 (어댑터 설정 · TUI 이름 · 모델 이름) 은 `.gitignore` (git 에 올리지 않을 파일을 적어 두는 목록) 로 막아 둔 `adapters.local/` 또는 데이터 폴더 (`%LOCALAPPDATA%\diode`) 에만 둬요.
- 공개 저장소로 되돌아오는 것은 사내 이름이 없는 일반 코드뿐이에요.
- 사내에서 고친 일반 코드를 되가져올 때는 diff (바뀐 곳을 보여 주는 비교 결과) 를 사람이 한 줄씩 봐요. 되가져오기 전에 사내 PC 에서 `python tools/diode_check.py --strict --internal-words "<사내 낱말 목록 파일>"` 을 돌려 0 인지 봐요 (낱말 목록은 사내 자리에만 두고 저장소에 두지 않아요 · 검사기는 낱말을 찍지 않아요).

## 검토 세션의 자리

- 사내 Claude 로 다이오드 코드를 검토할 때는 `D:\claude\diode` 에서 열어요.
- `D:\claude` 에서는 열지 않아요 — 방 (`D:\claude\room`) 과 소스를 한 세션이 같이 보게 돼요.
- 원자료가 있는 폴더 · works 저장소 루트 (`D:\OPENCODE` — 데이터를 프로그램 폴더에 두는 앱이 있어요) 에서도 열지 않아요.
- 검토 세션에도 안전벨트를 켜요 (L-20). 방이 아니므로 안전벨트 + `[질문]` 길이에요.
- 검토 대상은 공개 코드뿐이고 사내 월 한도 안에서 해요.

## 사내에서 할 일

- 사내 TUI 어댑터를 계약대로 만들고 계약 테스트를 통과시켜요. TUI 에 훅 (정해진 때에 자동으로 도는 검문 프로그램) 이 없으면 `room` 을 꺼요.
- KIT-1 · KIT-2 를 사내 TUI 판으로 다시 해요. 사내 Claude Code 판의 statusLine 입력 칸이 문서와 다르면 `--statusline` 을 맞춰요.
- 사내 모델 이름으로 KIT-6 (effort 별 비용) 을 재고, 사내 Claude Code 판에서 KIT-7 (허브가 뜨는지 · 창 · 환경 변수 · 도구 결과 모양) 을 다시 해요.
- `kit/run_kit.py` 를 사내 Windows 에서 `--python python` 으로 돌려요. 결과는 판정과 숫자만 공개 저장소로 가져와요.
- 사내 CLI 에 opencode (안쪽 일꾼으로 쓰는 프로그램) 가 어떻게 물려 있는지 (명령줄 · MCP · 하위 에이전트) 확인하고, 설정 `worker.command` (예 `["opencode", "run", "{prompt}"]`) 와 `policy.inner_tools` (사내 이름은 사내에서만 적어요) 를 맞춰요. Claude 가 안쪽 도구를 직접 부르는 길이 하나도 남지 않았는지 (훅 deny) 확인해요.
- `kit/run_opencode.py --opencode <사내 opencode>` 를 돌려 (가짜 로컬 모델 · 밖으로 나가는 요청 없음) 사내 판에서도 일꾼 부품과 셸 권한이 똑같이 동작하는지 봐요. 사내 모델 공급자 설정은 사내에서만 적어요.
- **9판 (가린 왕복) 도 사내에서 확인해요.** 가명 금고가 이 PC 에서 정말 암호화되는지 · 사내 LLM 이 가린 코드 조각을 제대로 판정하는지 · opencode 가 가릴 곳을 제대로 표시하는지예요. 아래 점검표 8–10 이고, 따라 하는 순서는 [MANUAL 의 작업 묶음 절](MANUAL.md#파일을-가려서-claude-에게-보내기--작업-묶음-9판) 에 있어요.
- **사내 확인 1차 답을 받아 설계에 반영했어요.** 답 자체 (사내 PC · 설정의 사실) 는 이 공개 저장소에 옮기지 않아요 — 설계에 필요한 결론만 코드 · 문서에 남겨요 (프롬프트는 표준 입력으로 · 안내 파일의 사전 단어 검사 · 일꾼 전용 에이전트 권한). Q28–Q32 (opencode 실행 · 사내 LLM 판정 시험) 는 보안 때문에 하지 않았어요 — 보안 부서의 답 뒤에 해요 (D7 은 형식을 어기면 막는 쪽이라 안전은 그대로예요).
- **아직 모르는 것**: 동기화 · 백업 · 원격 수집이 사전이 든 데이터 폴더를 가져가나 (사전은 사내 단어를 그대로 적은 글이에요 · 9판부터는 가명 금고 `vault\` 도 같은 폴더에 있어요 - 진짜 값과 토큰의 짝이라서 사전만큼 조심해요 · 사내에서 확인할 것) · 권한 모드 · `/effort max` · `opencode serve` · opencode 권한 기본값.
- 코드 전체를 최종 검토해요.

## 사내에서 할 일 - 순서 (점검표)

공개 저장소의 CI 가 GitHub 의 Windows (Git Bash · 진짜 Claude Code 2.1.318 · 진짜 opencode 1.19.5 · 가짜 서버) 에서 이미 돌린 시험이 있어요 ([kit/results-ci.md](../kit/results-ci.md)). CI = 코드를 올리면 자동으로 시험을 돌려 주는 장치예요. 사내 PC 에서는 **같은 시험을 다시 돌려 달라지는 곳만** 찾으면 돼요 - 달라지면 그것이 사내 환경의 차이 (관리형 설정 · 단말 보안 · 프록시 · 사내 판) 예요.

| 순서 | 할 일 | 도구 | 합격 | 달라지면 |
|---|---|---|---|---|
| 1 | 설치 | [INSTALL.md](../INSTALL.md) 1–6단계 | 각 단계의 **확인** 이 맞다 | 문제 해결 표 · 표에 없으면 출력 그대로 보고 |
| 2 | 점검 | `python diode.py setup --check --report` ([질문지](../kit/inhouse-questions.md) H1) | 개수 · 참거짓만 나온다 | 출력 전체를 옮긴다 (값이 없다) |
| 3 | 처음부터 끝까지 | `python kit/run_install.py` (H7) | I1–I6 모두 OK | 어느 줄이 실패했나 - I1 이면 마켓플레이스/설치가 막힌 것 (관리형 설정) |
| 4 | 훅 시나리오 | `python kit/run_hooks.py` (H2) | R01–R33 모두 OK | R17 이면 Git Bash 에서 `${CLAUDE_PLUGIN_ROOT}` 가 안 풀린 것 |
| 5 | 일꾼 연결 | `python kit/run_opencode.py --opencode <사내 opencode>` (H5) | R1–R4 모두 OK, **`.cmd` 껍데기면 R5 도 OK** | R5 실패는 명령 주입 방어가 뚫린 것 - 일꾼을 달지 않는다 |
| 6 | 눈으로 확인 | 정책 창 · 확정 창 · 말 봉인 창을 직접 연다 | 창이 맨 위에 보인다 · 한글 입력이 된다 (IME) · 글자 크기가 읽힌다 (DPI) | CI 는 "프로세스가 떴다" 까지만 안다 |

| 8 | 가명 금고 (9판) | 안쪽 터미널에서 `python diode.py project open` → `python diode.py project status` → (확인이 끝나면) `python diode.py project close` | `project status` 의 `protected` 가 `true` (DPAPI 로 암호화했다는 뜻이에요) · 금고 파일 자리 (`%LOCALAPPDATA%\diode\vault\`) 가 동기화 · 백업 · EDR (단말 보안 프로그램) 수집 대상이 아니다 - [질문지](../kit/inhouse-questions.md) Q10 과 같이 봐요 | `E-20` 이면 이 PC 에서 DPAPI 를 못 쓰는 거예요 (단말 보안 · 관리형 설정) - 작업 묶음을 쓰지 않아요. 수집 대상이면 금고가 다른 곳에 복사될 수 있어요 - 사내에서 정해요 (수집에서 빼거나 작업 묶음을 쓰지 않아요) |
| 9 | 가린 조각 판정 (D7 · 9판) | 합성 표본 (아래) 을 [SPEC 부록 A2](SPEC.md#부록-a2--가린-파일-묶음-조각의-판정-프롬프트-sp-20--고정-글) 프롬프트로 사내 LLM 에 한 조각씩 물어요 ([질문지](../kit/inhouse-questions.md) Q32 와 같은 방법) | 깨끗한 조각은 `pass` · 새는 조각은 `block` · 답은 한 줄 JSON - 숫자를 아래 칸에 적어요 | 새는 조각이 `pass` 로 나오면 D7 만 믿지 않아요 (사람의 확정 D8 이 마지막 문이에요). 깨끗한 조각이 자꾸 `block` 이면 너무 막아서 도구를 끄게 돼요 |

순서 8–10 의 합성 표본은 **지어낸 말과 수치만** 써요 (사내 값 · 사내 코드는 쓰지 않아요).

- **깨끗한 조각 (순서 9)**: 이름 · 수치 · 경로를 모두 `PH_K7Q2` 같은 토큰으로 바꾼 짧은 코드 · 표 · 글이에요 (예: `host = "PH_K7Q2"`).
- **새는 조각 (순서 9)**: 같은 모양인데 지어낸 이름 · 공정 · 수치 · 호스트를 가리지 않고 일부러 남긴 것이에요 (예: `host = "db01.example.corp"` · `temp = 350` · `노을공정`). 순서 9 는 D7 만 따로 시험해요 - 잔여 검사 R1–R6 은 거치지 않고 프롬프트로 바로 물어요.
- **합성 파일 (순서 10)**: 지어낸 이름 · 수치 · 호스트가 든 문서 · 표 · 코드 파일을 몇 개 만들어요. 사전에는 지어낸 단어 몇 개만 넣어요 (정책 창).

| 칸 | 적을 것 (숫자 · y/n 만) |
|---|---|
| 순서 8 · `protected` 가 `true` 였나 | y / n |
| 순서 8 · 금고 자리가 동기화 · 백업 · 수집 대상인가 (Q10 과 같이) | y / n / ? |
| 순서 9 · 깨끗한 조각 수 · 그중 `pass` 로 나온 수 | `__` 개 중 `__` 개 |
| 순서 9 · 새는 조각 수 · 그중 `block` 으로 나온 수 | `__` 개 중 `__` 개 |
| 순서 9 · 한 줄 JSON 으로 바르게 답한 횟수 | `__` 번 중 `__` 번 |
| 순서 10 · 합성 파일 수 · opencode 가 표시한 곳 (확정 창에 보여요) | `__` 개 · `__` 곳 |
| 순서 10 · 자동 가림 (확정 창의 AUTO) | `__` 곳 |
| 순서 10 · R 검사에 걸려 다시 낸 횟수 | `__` 번 |

[제안] 순서 9 의 합격선은 새는 조각을 `pass` 로 놓친 것이 0 이에요. 놓치면 D7 은 문이 아니라 참고로만 보고 사람의 확정 (D8) 에 기대요. 깨끗한 조각을 `block` 한 수와 순서 10 의 숫자는, 적어 온 숫자를 본 뒤에 사내에서 정해요.

공개 저장소로 되가져오는 것은 **판정과 숫자** (OK/실패 줄 · 개수) 뿐이에요. `kit/out/` 안의 파일 (시스템 프롬프트 원문이 있어요) 과 사내 이름 · 경로 · 주소는 옮기지 않아요.
