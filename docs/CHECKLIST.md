# Diode 사내 검증 체크리스트 — 에이전트용

> **개발 중 (v0.0) — 이 체크리스트를 모두 통과하기 전에는 real data(실데이터)를 사용하지 않습니다.** 모든 확인은 synthetic data(가상 자료)로만 진행합니다.

**사용자용 한 줄 프롬프트:** 회사 Claude Code에 아래 문장을 그대로 붙여넣으면, 이 문서 순서대로 검증을 진행합니다.
"`D:\claude\diode\docs\CHECKLIST.md`를 끝까지 읽고 순서대로만 진행해. 사내 단어 · 사내 경로 · 사내 주소 · 키는 출력하지 말고, [질문] 표시가 있는 곳에서는 멈추고 나한테 물어봐. 마지막에 9번 보고 양식으로만 보고해."

이 문서는 **에이전트가 순서대로 따라 하는 점검표**입니다. 에이전트 = 사람 대신 명령을 실행하는 AI 도우미입니다. 각 단계는 `명령 → 확인 → 실패하면` 순서입니다. 설치 자체는 [INSTALL.md](../INSTALL.md)가 다루고, 이 문서는 **설치가 이 PC에서 정말 지켜지는지**를 확인합니다. 왜 이런 단계가 있는지는 [사내 마무리 경계](INHOUSE.md)에 있습니다.

## 0. 목표와 규칙

**목표**: Diode가 이 PC의 **모든 Claude Code 세션에서 꺼지지 않고 켜져 있는지**(전역) 확인하고, 사외에서는 확인할 수 없었던 것(사내 버전 · 창 · 가명 금고 · 사내 LLM 판정 · opencode 표시)을 하나씩 확인한 뒤 **숫자와 y/n만** 보고합니다.

**규칙 — 반드시 지켜야 할 사항**

1. **명령은 이 문서에 적힌 것만** 실행합니다. 명령은 한 번에 하나씩 실행하고, 결과를 확인한 뒤 다음 단계로 넘어갑니다.
2. **가상 자료만** 사용합니다. 사내 파일 · 사내 코드 · 사내 단어를 테스트에 넣지 않습니다. 사전(`%LOCALAPPDATA%\diode\dictionary.json`) · 설정 · 금고(`vault\`)는 열지도 출력하지도 않습니다.
3. **출력하지 않는 것**: 사내 단어 · 사내 경로 · 사내 호스트 · 사용자 이름 · 키 · 토큰 · `kit\out\` 안의 파일(시스템 프롬프트 원문이 있습니다). 보고에는 **OK/실패 줄과 숫자 · y/n**만 적습니다.
4. **관리자 권한을 사용하지 않습니다.** 3단계의 관리형 설정(managed settings)은 회사 IT가 하는 일입니다. 에이전트는 파일 내용만 보여 주고 **[질문]으로** 사람에게 넘깁니다.
5. **보호를 끄거나 우회하지 않습니다.** 실패하면 출력을 그대로 보여 주고 멈춥니다. `policy.real_data`(실데이터 켜기)는 에이전트가 절대 켜지 않습니다.
6. 종료 코드: `0` OK · `1` 점검 실패 · `2` 사용법 오류 · `3` 사람 확인 필요. 테스트 출력은 `결과: OK` · `결과: 확인 필요` · `결과: 점검 실패` 줄로 끝납니다.
7. 테스트 명령(`kit\run_*.py`)은 **임시 폴더와 127.0.0.1의 모의 서버**만 사용합니다 — 이 PC의 Claude 설정을 변경하지 않고, 회사 외부로 요청을 보내지 않습니다.
8. 이 체크리스트는 **`D:\claude\diode`에서 연 Claude Code 세션**에서 진행합니다. 방(`D:\claude\room`)에서는 셸이 막혀 있고, `D:\claude`나 원자료 폴더에서는 열지 않습니다.
9. 에이전트는 내부 도구(opencode · 사내 LLM)를 직접 호출하지 않습니다 — Diode hook이 막는 경로이고, 막는 것이 맞습니다. 내부에서 할 일은 **[질문]으로** 사람에게 넘깁니다.

## 1. 설치가 끝났는지

```text
python "D:\claude\diode\diode.py" version
claude plugin list
python "D:\claude\diode\diode.py" setup --check --report
```

- **확인**: `claude plugin list`에 `diode@diode`가 있고 `Status:`가 `enabled` · `Read from:`이 `D:\claude\diode`입니다. 점검의 마지막 줄이 `결과: OK`입니다(출력은 개수 · 참/거짓뿐입니다).
- **실패하면**: 설치가 끝나지 않은 것입니다. [INSTALL.md](../INSTALL.md) 1–6단계를 먼저 마치고 돌아옵니다. `결과: 확인 필요`가 나오면 출력의 `‼` 줄을 그대로 보여 주고 **[질문]합니다**.

## 2. 전역 확인 — 지금 이 PC 에서 Diode 를 끌 수 있나

사용자 범위 설치는 "새 세션마다 켜짐"이지만, **끄는 방법이 남아 있습니다**(사외에서 실제 Claude Code 2.1.318로 확인 · 2026-11-28). 이 테스트는 그 방법들로 꺼 보고 사전 단어가 그래도 막히는지 확인합니다(임시 HOME · 모의 서버 · 가상 단어).

```text
python "D:\claude\diode\kit\run_global.py"
```

| 줄 | 끄는 방법 |
|---|---|
| G1 | (대조) 끄는 설정 없음 — **막힘**이어야 합니다 |
| G2 | 어떤 폴더의 `.claude\settings.json`에 `"enabledPlugins": {"diode@diode": false}` 한 줄 |
| G3 | 같은 줄을 `.claude\settings.local.json`에 |
| G4 | 어떤 폴더의 `.claude\settings.json`에 `"disableAllHooks": true` |
| G5 | Claude Code를 `--settings`로 열며 끔 |
| G6 | 사용자 설정(`/plugin` 화면에서 끄는 것과 같은 위치) |
| G7 | `claude plugin uninstall diode@diode`로 지움 |

- **확인**: 관리형 설정이 없는 PC라면 `G1 막힘`이고 G2–G7은 `꺼짐`이며 마지막 줄이 `결과: 확인 필요`(종료 코드 3)입니다 — **이것이 지금의 정상 상태이며, 3단계가 필요하다는 뜻입니다.** 이미 모두 `막힘`이고 `결과: OK`가 나오면 회사에 관리형 설정이 이미 있는 것입니다 → 4단계로 넘어갑니다.
- **실패하면**: `G0 실패`가 나오면 마켓플레이스 추가 · 설치 단계부터 막힌 것입니다(회사 정책일 수 있습니다) — 출력을 보여 주고 **[질문]합니다**. `G1 꺼짐`이나 `결과: 점검 실패 (G1 …)`가 나오면 설치 · 설정 · `python` 명령이 잘못된 것입니다 → 1단계로 돌아갑니다.

## 3. 관리형 설정으로 Diode 를 늘 켜 두기 — 회사 IT 가 합니다

Claude Code의 설정은 **관리형 설정 > 명령줄 > 프로젝트 로컬 > 프로젝트 > 사용자** 순서로 우선 적용됩니다([문헌: Claude Code settings 문서](https://code.claude.com/docs/en/settings) · 2026-11-28). 관리형 설정에서 Diode를 켜 두면, 2단계의 G2–G7 어느 방법으로도 끌 수 없습니다. **사외에서 2.1.318로 아래 최소 설정을 적용하고 2단계 테스트를 실행해 G2–G7이 모두 막히는 것을 확인했습니다**(리눅스 · 격리한 테스트 환경).

**[질문]** 에이전트는 아래를 사람에게 보여 주고 멈춥니다: "Diode를 이 PC의 모든 Claude Code 세션에서 끌 수 없게 하려면, 회사 IT가 관리형 설정에 아래 두 키를 넣어야 합니다. 관리자 권한이 필요해서 저는 하지 않습니다. IT에 요청해 주시겠어요? 넣은 뒤 알려 주시면 4단계로 확인하겠습니다."

**최소 설정**(Windows 파일 위치: `C:\Program Files\ClaudeCode\managed-settings.json`)

```json
{
  "extraKnownMarketplaces": {
    "diode": { "source": { "source": "directory", "path": "D:\\claude\\diode" } }
  },
  "enabledPlugins": { "diode@diode": true }
}
```

- `extraKnownMarketplaces` — 이 PC의 `D:\claude\diode`를 마켓플레이스 `diode`로 등록합니다. 이름은 반드시 `diode`로 둡니다(사용자 범위의 같은 이름 항목을 대신합니다).
- `enabledPlugins`의 `"diode@diode": true` — Diode를 강제로 켭니다. 어떤 프로젝트 · 사용자 설정 · 명령줄도 끄지 못합니다. 사용자가 삭제해도 다음 세션에 다시 적용됩니다(G7).

**IT가 반드시 알아야 할 것**

- **관리형 설정이 전달되는 경로는 한 PC에서 하나만 사용됩니다.** 서버 관리 설정(claude.ai 관리 콘솔) → MDM · 레지스트리(`HKLM\SOFTWARE\Policies\ClaudeCode`의 `Settings` 값) → 위 파일 순서로, **먼저 정책이 있는 하나만** 사용합니다([문헌: plugins/org 문서](https://code.claude.com/docs/en/plugins/org)). 회사가 이미 콘솔이나 레지스트리로 관리형 설정을 배포하고 있다면, 위 두 키를 **그 위치에** 넣어야 합니다 — 파일에 넣으면 무시됩니다. 여러 곳을 합치려면 `"managedSourcesBehavior": "merge"`(2.1.242 이상)를 사용합니다. `HKCU`(사용자 쪽 레지스트리)는 사용자가 수정할 수 있어 관리 수단이 아닙니다.
- **JSON이 틀리면 Claude Code가 아예 켜지지 않습니다.** 넣기 전에 JSON 검사기로 확인합니다. 경로의 `\`는 `\\`로 표기합니다.
- **선택(회사가 정할 일 · 필요 없으면 넣지 않습니다)**:
  - `"strictKnownMarketplaces": [{ "source": "directory", "path": "D:\\claude\\diode" }]` — 이 마켓플레이스 외에는 아무것도 추가하지 못하게 합니다(다른 플러그인을 사용하는 사람은 막힙니다).
  - `"disableSideloadFlags": true` — `--plugin-dir`로 다른 플러그인을 몰래 로드하지 못하게 합니다.
  - `"allowManagedHooksOnly": true` — 관리형 hook과 강제로 켠 플러그인(Diode)의 hook만 실행되고, **사용자 · 프로젝트의 다른 hook은 모두 막힙니다**. Diode를 보호하는 데는 필요 없습니다(최소 설정만으로 G2–G7이 막혔습니다).
  - `"disableAllHooks"`는 관리형 설정에 **넣지 않습니다** — 넣으면 Diode의 hook까지 모두 꺼집니다.
- **되돌리기**: IT가 위 파일(또는 그 키)을 삭제하면 사용자 범위 설치 상태로 돌아갑니다.
- **확인되지 않은 것 [미확인]**: Windows에서 `directory` 마켓플레이스 경로(`D:\\claude\\diode`)를 어떻게 대조하는지는 문서에 없습니다 — 4단계 테스트로 확인합니다.

## 4. 관리형 설정이 걸린 뒤 — 전역 확인을 다시

```text
python "D:\claude\diode\kit\run_global.py" --expect locked
claude plugin list
```

- **확인**: G1–G7이 모두 `막힘`이고 마지막 줄이 `결과: OK`입니다. `claude plugin list`에서 `diode@diode`가 관리형 설정(managed)에서 켜졌다는 표시가 보일 수 있습니다(문구는 버전마다 다를 수 있습니다). 대화형 Claude Code에서 `/status`를 열면 설정 출처에 관리형 설정(Enterprise managed settings)이 보입니다.
- **실패하면**: `꺼짐`이 남은 줄 번호만 보고하고 멈춥니다. 대부분 관리형 설정이 이 PC에 적용되지 않은 것입니다(다른 출처가 먼저 사용됨 · 파일 위치 · JSON 오류 · 경로 표기). **[질문]으로** IT에 넘깁니다.

## 5. 사내 판에서 시험 다시 돌리기

사외 CI가 Windows에서 이미 실행한 테스트입니다([kit/results-ci.md](../kit/results-ci.md)). 사내 PC에서는 **달라지는 곳만** 찾습니다 — 달라지는 부분이 곧 사내 환경의 차이(관리형 설정 · 단말 보안 · 프록시 · 사내 버전)입니다.

```text
python "D:\claude\diode\kit\run_install.py"
python "D:\claude\diode\kit\run_hooks.py"
python "D:\claude\diode\kit\run_opencode.py" --opencode "<사내 opencode 명령>"
```

- **확인**: 각 줄이 `OK`이고 마지막 줄이 `결과: OK`입니다 — `run_install`은 I1–I6, `run_hooks`는 R01–R33(화면이 없으면 창 시나리오 몇 개는 건너뜁니다), `run_opencode`는 R1–R4(opencode가 `.cmd` 래퍼이면 R5도).
- **실패하면**: 실패한 **줄 번호만** 보고합니다. `I1`은 설치가 막힌 것 · `R17`은 Git Bash에서 `${CLAUDE_PLUGIN_ROOT}`가 치환되지 않은 것 · `R5`는 명령 주입 방어가 뚫린 것입니다(`R5`가 실패하면 opencode를 내부 에이전트로 연결하지 않습니다). `<사내 opencode 명령>`은 사람에게 **[질문]으로** 받고, 보고에는 적지 않습니다.

## 7. 가린 왕복 (9판) 확인

따라 하는 자세한 순서는 [MANUAL › 작업 묶음](MANUAL.md#파일을-가려서-claude-에게-보내기--작업-묶음-9판)에 있습니다. **여기서 사용하는 이름 · 수치 · 호스트는 모두 가상 자료**(예: `노을공정` · `350` · `db01.example.corp`)여야 하고, 사전에도 가상 단어 몇 개만 넣습니다(정책 창에서 사람이).

**A. 가명 금고가 암호화되는가** — 사람이 내부 터미널에서 직접 입력합니다(에이전트가 호출하면 `E-30`으로 거절됩니다).

```text
python "D:\claude\diode\diode.py" project open
python "D:\claude\diode\diode.py" project status
```

- **확인**: `project status`의 `"protected": true`(Windows DPAPI로 암호화했다는 뜻). 그리고 **[질문]** "`%LOCALAPPDATA%\diode\` 폴더가 동기화 · 백업 · 단말 보안(EDR) 수집 대상인가요?" — 대상이면 금고가 다른 곳으로 복사될 수 있으니 사내에서 정합니다(수집에서 빼거나 작업 묶음을 사용하지 않음).
- **실패하면**: `E-20`이 나오면 이 PC에서 DPAPI를 사용할 수 없는 것입니다 → 작업 묶음을 사용하지 않습니다.

**B. 사내 LLM이 가린 조각을 제대로 가르는가(D7)** — 에이전트는 아래 가상 조각과 [SPEC 부록 A2](SPEC.md#부록-a2--가린-파일-묶음-조각의-판정-프롬프트-sp-20--고정-글)의 프롬프트를 글로 준비만 하고, **[질문]** "이 프롬프트에 조각을 하나씩 넣어 사내 LLM에 물어보고, 조각마다 `pass` / `block`과 답이 한 줄 JSON이었는지 알려 주세요"로 사람에게 넘깁니다(내부 도구는 에이전트가 호출하지 않습니다 · 규칙 9).

- 깨끗한 조각 5개 이상: 이름 · 수치 · 경로를 모두 `PH_K7Q2` 같은 토큰으로 바꾼 짧은 코드 · 표 · 글(예: `host = "PH_K7Q2"` · `temp = PH_M3X9`).
- 새는 조각 5개 이상: 같은 형식인데 가상의 이름 · 수치 · 호스트를 일부러 남긴 것(예: `host = "db01.example.corp"` · `temp = 350` · `노을공정 수율`).
- **확인**: 깨끗한 조각은 `pass`, 새는 조각은 `block`, 답은 한 줄 JSON. **새는 조각을 `pass`로 놓친 수가 0**이어야 합니다 [제안].
- **실패하면**: 새는 조각이 `pass`로 나오면 D7은 참고로만 보고 사람의 승인(D8)이 마지막 관문입니다 — 숫자를 그대로 보고합니다.

**C. opencode가 가릴 곳을 제대로 표시하는가** — 가상 파일 몇 개(문서 · 표 · 코드)로 opencode에게 "이 파일들을 가려서 Claude에게 보내 줘"라고 시킵니다.

- **확인**: 승인 창이 뜹니다. 창 맨 위의 FILES · TOKENS · **AUTO**(Diode가 자동으로 가린 곳 — 많을수록 opencode가 표시를 빠뜨린 것)와, 잔여 검사(R1–R6)에 걸려 다시 낸 횟수를 적습니다. 보내지 않고 [버리기]를 눌러도 됩니다.
- 끝나면 사람이 `python "D:\claude\diode\diode.py" project close`로 묶음을 닫습니다(금고를 삭제합니다).
